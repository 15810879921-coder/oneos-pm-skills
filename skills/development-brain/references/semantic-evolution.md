# 主动识别与自动进化

## 语义触发

不要求用户写 `$development-brain`。结合本轮自然语言、已打开仓库和连续会话上下文判断开发生命周期：

- **开发开始**：明确要求实现、修改、调试、重构、修复、构建、补测试、提交代码、继续开发，或准备执行首次代码/Git/开发平台写入。先自动执行开发大脑预检，预检完成前不得写入。
- **开发进行中**：正在阅读代码、编辑、运行开发侧构建/测试、处理编译错误、准备提交或延续同一个已定位开发任务。沿用同一预检回执；范围、仓库、分支或任务发生实质变化时重跑预检。
- **开发结束**：目标实现已完成，并同时存在可定位的代码变化以及构建、测试、静态检查、提交或 MR 等完成证据。自动执行结束复盘。

纯产品/需求梳理、正式 QA 验收、生产发布、架构概念解释、代码知识问答和只读报告不触发。仅因回复结束、计划写完、任务被阻塞、用户暂停、测试失败或代码尚未完成，不得判定为开发结束，也不得触发知识进化。

当开发语义属于 Yunxiao 正式开发任务或 Bug 时，业务执行仍交给 `$yunxiao-development-delivery`；开发大脑只提供预检、约束引用和复盘，不抢占任务选择，不新增平台写入。

## 自动进化阶梯

1. **首次闭环**：新模式达到 `90–100` 分且通过所有硬门槛，自动记录为 `candidate`。
2. **再次命中**：先匹配现有候选，不创建重复记录。只有第二个独立完成的开发任务再次证明同一现象、根因、预防动作和适用范围，且本轮达到 `95–100` 分，才能提升原 ID 为 `confirmed`。
3. **正式生效**：远端 GitHub 推送和 `main` 读回成功后才算进化完成。新确认规则只作用于后续任务或重新执行预检后的工作，不追溯扩大本次任务范围。

“独立”必须同时满足：任务/缺陷标识不同；提交或 MR 证据集合不同；验证执行与结果不同。同一任务的重试、续跑、补充说明、重复构建、回归测试或同一提交的再次验证只算一组证据。

## 自动确认禁区

以下规则无论得分和重复次数如何都不得自动转为 `confirmed`，必须由何斐明确确认：

- 删除、覆盖、不可逆迁移等破坏性操作；
- 权限扩大、越权访问、绕过认证/审批/安全门禁；
- 生产配置、生产数据、上线、发布或回滚授权；
- 强推、重写共享 Git 历史或绕过分支保护；
- 密码、密钥、Cookie、令牌及其他敏感凭据的读取、保存或传递；
- 降低测试、审计、回读、人工确认或既有安全标准。

与仓库实时规则、任务材料、用户指令、安全规则或既有 `confirmed` 冲突时不得自动确认；只输出冲突与所需裁决。

## 写入边界与失败回执

进化只允许修改开发大脑知识及其发布包，不得借此修改业务代码、云效任务/Bug、Git/MR、流水线、测试结果或生产环境。权威仓脏、远端漂移、权限不可用、校验失败、无法证明独立证据或推送读回失败时，不做知识写入并输出：

```text
开发大脑：进化未落盘
拟处理记录：<ID 或新候选摘要>
失败原因：
两组独立证据：满足|不满足（依据）
```
