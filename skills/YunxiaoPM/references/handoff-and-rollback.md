# 交棒门禁与回退最小集

## 交棒门禁（待开发）

| 情形 | 规则 |
|---|---|
| 【交付】描述已是 AutoPRD 正式说明（非占位） | 需求与对应【交付】必须已回读同一产品快照编号/哈希；通过后允许交棒，Plan 列快照 + 交付任务编号 + 已解析负责人及来源 |
| 【交付】描述仍为 `等待设计任务完成后自动填入` | **仍允许交棒**，但 Plan **必须**勾选风险项「交付描述仍为占位，技术侧仅可凭需求 AutoRDO 稿理解」；回报**首行标红**该风险；**禁止**静默交棒假装材料齐全 |
| 口令同时带原型且要求设计完成 | 先走步骤 4（AutoPRD+附件+产品快照）成功并回读，再交棒，不再勾占位风险 |

产品在设计完成或交棒后修改 PRD/原型时，执行`刷新产品快照`。该命令只替换需求和对应【交付】的快照受管区块，不改变状态、负责人、关系、迭代或计划；开发侧据新哈希判断是否刷新任务方案。

## 回退 / 变更（最小集 · 兼容计划开始不篡改）

| 场景 | 规则 |
|---|---|
| 待开发 → 退回设计中 | 先用`preflight-rollback-to-design`冻结需求、【交付】计划开始、原设计状态/关系与编号区块；再用`apply-rollback-to-design`新开设计任务、正式挂到同一【交付】、把需求回退设计中并更新「工作项编号（系统）」。旧设计保持已完成，**交付计划开始不改**；预检后任何对象、关系、计划开始或编号漂移均零写入。 |
| 设计完成后需求大变 | 不自动改状态；Plan 询问是否回退设计中并新开设计编号；更新 AutoPRD 段；AutoRDO 段保留并追加「变更纪要」 |
| 开发后取消需求 | 先用`preflight-cancel-downstream`冻结需求、【交付】、未执行发布批次与正式关联；确认不存在真实生产证据后，执行`apply-cancel-downstream`取消仍活跃的需求、【交付】与未执行批次。不删编号区块、不改已写计划开始；已完成开发/测试、已关闭缺陷、MR与流水线证据只读保留。若已有真实生产证据，停止并交由发布Skill先回滚。 |
| 度量含义 | 交付计划开始保留 = 全周期仍从首次开工起算；回退重做会拉长日历工时——回报注明「含回退重做」 |

回退设计或取消需求会改变状态/范围，仍须走 Plan 并确认；同一幂等键下只补未完成动作或官方回读时不重复确认，范围漂移则重新Plan。
