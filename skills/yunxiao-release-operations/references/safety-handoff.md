# 安全实施与跨角色交接

## 写入前

1. 明确组织、项目、项目ID、工作项类型、工作项编号和流程模型。
2. 把项目和迭代显示名解析为唯一ID；零个或多个匹配均停止。
3. 区分读取、规划和写入授权。文档、审计和“为什么”不授权修改。
4. 所有云效平台操作只使用官方 `aliyun devops` CLI；认证只来自本机环境变量，不记录账号、密码、Cookie、Token、OTP、Webhook密钥或私钥，也不使用浏览器或连接器回退。
5. 备份相关规则的触发、条件、动作、顺序、启用状态和执行账号。

`准备发布：迭代=<名称>`只授权读取该迭代正式`【交付】`及其`ASSOCIATED→需求`关系，自动选入非延期且已测试完成的候选、运行A/B/C/D分类，并在通过后创建/复用由`项目ID+迭代ID+排序后的A类需求ID+排序后的无关联单据已完成BugID+release_prepare`唯一确定的顶层`【发版】`任务。需求无需直接关联迭代。须按源交付标签判定端别为`Web`或`小程序`（`PC`视为`Web`）；混端零写入。它以迭代为起点，正式关联A类需求、这些需求的多个源【交付】和同迭代的无关联单据已完成Bug；该Bug必须真实为`已完成`或`已关闭`且不存在任何正式关联单据（任何关系类型、任何工作项）。**Web**冻结唯一活动生产流水线；**小程序**不要求生产流水线。test部署、QA证据、用例执行、缺陷闭环、审批人、发布窗口、回滚方案和生产验证计划均为可选记录，缺失时写`未配置/未自动验证`，不阻断准备或执行。`需求=<ID,...>`仅允许热修复、灰度或明确局部发布时使用。C/D非空、A为空、范围漂移、项目/迭代/顶层或正式关系冲突，或（仅Web）排除退役定义后活动生产流水线缺失/冲突时零写入；B类延期或尚未测试完成需求不阻塞但不得混入本批。

直接流水线口令是例外的最小执行授权：只授权按名称唯一匹配并启动一次现有流水线。它不授权修改流水线定义、绕过内部审批、写工作项状态或重复提交。

`执行发布`按端别分流：**小程序**跳过云效生产流水线与外部证据，默认写入`发布完成`并交接产品验收；**Web**只为冻结的唯一生产流水线创建首次发布尝试，或按已保存的`releaseAttemptId`接续同一次未终结尝试。审批人字段、发布窗口、回滚方案、生产验证计划和回调证据缺失不阻断生产；流水线原生审批节点仍不得绕过。监控中断、执行中或验证中不等于失败，仍接续原尝试。当前尝试一旦明确失败，重复`执行发布`只允许接续/返回该尝试的回滚和修复交接，永远不能创建新的生产执行；若为发布完成，只允许收尾。

`执行回滚：发版任务=<ID> 原因=<问题> 证据=<ID或URL>`授权对尚未由产品验收关闭、且具有可核验线上问题证据的精确发版任务执行一次主动回滚。它不授权重开`已完成/已关闭`生命周期，不接受临时覆盖回滚目标，不自动重新发布，也不扩大到其他需求或服务。

`重新发布：发版任务=<ID> 回归证据=<ID或URL>`是失败后创建新生产尝试的唯一授权。确认原范围不变、受影响Bug已关闭并提供当前回归证据后，以最大`attemptNo+1`生成新的`releaseAttemptId`，记录`attemptType=re_release`和`previousAttemptId`。它不接受手工覆盖迭代/范围，不复用旧执行；自定义QA/test部署/逐Bug JSON、审批字段和观察窗口有则记录，缺失格式不阻断。重发再次失败后仍必须完成下一轮修复再使用本命令。

自动或主动回滚只允许使用发版任务中已保存且可验证的回滚方案和稳定版本锚点。缺少这些内容不阻断生产执行，但必须返回`自动回滚=false`；不得猜测目标版本、修改回滚定义、重复回滚、删除发布证据、自动重试生产或擅自回退需求业务状态。生产流水线成功且环境、范围和执行ID回读一致即可技术发布完成；可用生产检查照常记录，缺失检查交产品验收确认。

流水线执行命令在失败后自动读取失败日志，不需要独立分析口令；使用`查询发布：发版任务=<ID>`复查该任务下的历史执行日志属于只读授权范围。不得以需求ID或流水线执行ID替代发版任务ID。返回或保存前必须脱敏密码、Token、Cookie、AccessKey、私钥、认证头和密钥变量值；无法安全脱敏时只返回日志位置、失败步骤和访问限制。

## 线上修改

- 一次只改一个明确对象，保存后重新打开核验。
- 每个自动流转必须检查预期当前状态。
- 标题前缀识别阶段，正式父子/关联关系识别归属，二者缺一不可。
- 标签仅表示业务模块。
- 原生规则不能读取关联任务标题或不能更新关联需求时，使用`integration_bridge`、`manual`或`not_supported`，不得伪装为原生自动化。
- 新规则不补触发历史事件；历史修复单独记录。
- 手工准备状态不能作为自动化通过证据。

## 验证与结果

每次写入后等待5–30秒，检查状态、正式关系、执行日志和后继规则。结果只使用：

- `通过`
- `异步通过`
- `未触发`
- `误触发`
- `阻塞`

至少执行一个负向场景：错误源状态、无正式关系、错误标题前缀、重复事件、部分资产完成或错误环境。

## 交接协议

交接给另一个Skill时输出：

```text
来源Skill：
目标Skill：
项目名称/ID：
迭代名称/ID：
需求编号/当前状态：
正式关联任务：
发版任务顶层关系及其迭代关系：
本批源交付/无关联单据已完成Bug正式关联：
代码/测试/发布资产：
已验证证据：
生产验证计划/结果：
问题现象/影响范围/问题证据：
回滚执行/前后版本/恢复验证：
未完成项：
幂等键或事件ID：
允许的下一动作：
建议下一口令：
```

接收方必须重新读取真实状态，不能只相信交接文字。已满足的动作按幂等成功处理，缺失或冲突时停止。

## 状态所有权

| 范围 | 所有者 |
|---|---|
| 待处理至待开发、范围变更、生产后产品验收与交付关闭 | `YunxiaoPM` |
| 待开发至开发完成、代码资产、缺陷修复 | `yunxiao-development-delivery` |
| 待测试/测试中至测试完成、用例与缺陷复测 | `YunxiaoQA` |
| 测试部署证据、发布中、生产验证、发布完成/失败、回滚与问题反馈 | `yunxiao-release-operations` |

边界动作可由来源Skill创建下阶段资产，但目标Skill拥有下阶段的真实执行和完成结论。

发布/验收失败后的交接固定为：release/PM→`YunxiaoQA 接收发布回流`→`yunxiao-development-delivery 修复bug|处理发布回流`→`YunxiaoQA 验证发布回流`→`yunxiao-release-operations 重新发布`。每一步都必须重读真实状态和前序受管证据；不得从失败或回滚成功直接跳到生产重试。

## 停止条件

遇到验证码、OTP、登录批准、权限提升、发版任务或迭代无法唯一解析、发版任务存在`TASK_SUB→【交付】`父子关系、源交付/无关联单据已完成Bug与迭代或需求正式关系冲突、排除退役定义后活动流水线仍无法区分、生产范围不清或必填运行参数缺失时停止对应写操作并请求最少必要信息。审批人、发布窗口、回滚方案、生产版本锚点、生产验证计划或回调证据缺失只记录风险，不阻断生产；缺少回滚条件时关闭自动回滚。审批等待、权限阻塞、监控不可用、可选证据缺失、运行中和状态未知不得当作失败终态，不得因此触发回滚。已经`已完成/已关闭`的发布不得由本Skill重开，转交`YunxiaoPM`建立线上缺陷/热修复生命周期。

## 回滚

先禁用本次新增规则或桥接入口，再恢复修改前配置。保留任务、关系、执行日志、生产Tag/发布Commit、制品摘要和发布证据。删除规则、任务、MR、流水线或测试资产需要单独授权。
