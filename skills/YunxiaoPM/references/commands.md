# 口令面

```text
记录需求：…；项目ID=…或项目=（未给ID时Plan点选）；交付端=Web|小程序|共用服务；优先级=紧急|高|中|低；标签=…；提交部门=…；提交人=…；交付负责人=姓名或userId；推进至=暂不推进|已确认|分析中|设计中|设计完成|待开发|待开发(快轨)
受理确认：ONEOS-xx
开始分析：ONEOS-xx          → 按交付端建【交付】+【分析】（Web|小程序=1套；共用服务=Web+小程序共2套）并回报编号
开始设计：ONEOS-xx；交付任务=…；分析任务=… → 各端【设计】+收口对应分析（共用服务须覆盖两端或口令显式两套编号）
设计完成：ONEOS-xx；设计任务=…；原型=…
刷新产品快照：需求=ONEOS-xx；交付任务=ONEOS-a；快照文件=… → 仅更新需求/交付快照区块并回读，不改状态/负责人
交棒开发：ONEOS-xx；交付任务=…；[交付负责人=姓名或userId] → 待开发 + 全部端侧交付使用已解析负责人（共用服务须两条均交棒）
快轨待开发：ONEOS-xx；[交付负责人=姓名或userId] → 待开发 + 按交付端建【交付】+【设计】（无【分析】；共用服务=2套）+ 已解析交付负责人
编号直推：分析任务=ONEOS-b / 设计任务=ONEOS-c；[交付负责人=姓名或userId] → 收口未完成计划完成 + 需求待开发 + 已解析交付负责人
创建迭代：交付端=Web|小程序；版本类型=主|副|子；交付任务=ONEOS-a,ONEOS-b,…；名称前缀=…
关闭迭代：迭代ID=…
拉取待验收需求：发版任务=TASK-900
验收通过：发版任务=TASK-900；验收人=…；证据=…
验收不通过：发版任务=TASK-900；验收人=…；原因=…；证据=…
AutoRDO：…（粘贴聊天/附录音）→ 再记录需求
```

版本自动规则：取同前缀下最大 `Vx.y.z`（旧 `Vx.y` 视为 `Vx.y.0`）再按主/副/子递增；迭代名=`{前缀}{新版本}`。

**交付端 → 交付条数：** `Web`/`小程序` → 开始分析或快轨建 **1** 条【交付】；`共用服务` → 建 **2** 条（Web+小程序，均 ASSOCIATED→同一需求）。详见 [settled-rules.md](settled-rules.md) · [stage-flow.md](stage-flow.md)。

**端侧标签：** 每条【交付】建单后必打 `Web` 或 `小程序`（与模块标签并存），单端、双端均须打。

**PJ 项目**：命令给出项目 ID且官方唯一回读时直接锁定；否则新建需求/迭代前须点选实时项目。禁止使用缓存默认值。见 [project-selection.md](project-selection.md)。

**交付负责人**：优先读取命令；未给时读取当前项目配置。两者都必须由官方成员查询唯一解析并在写后回读；无配置或0/多命中则停，不使用固定人名兜底。

后续推进口令**优先显式带任务编号**；未带则读「工作项编号（系统）」；仍无则询问；**禁止按标题补全**。

开发前回报止于交棒；生产发布完成后，本Skill按[release-acceptance.md](release-acceptance.md)执行产品验收闭环。
