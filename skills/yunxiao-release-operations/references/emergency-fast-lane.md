# 何斐专属紧急发版快车道

本规则只适用于已通过官方 CLI 当前用户回读、且身份精确匹配 `何斐` 的操作者。姓名、口头授权、任务负责人或聊天截图不能替代身份校验。普通用户和普通发版继续执行完整的 `准备发布 → 执行发布 → 生产验证` 流程；不得把本快车道扩展为全员绕过。

## 固定顺序

```text
identity-verified → release-execute → audit-record → task-writeback → post-release-verify
```

快车道的含义是：身份通过后先执行已授权的既有发布动作，再把紧急原因和结果追加回同一个发版任务。它不修改流水线、不绕过原生审批、不新建第二个发版任务，也不改变生产执行的既有幂等、回滚和验证规则。

## 最低安全门禁

执行前必须能回读并记录以下四项：

- `operator-identity`：官方 CLI 当前用户的唯一身份 ID 与姓名 `何斐`；
- `release-task-scope`：唯一发版任务 ID、冻结范围和当前状态；
- `artifact-version-build`：发布版本与构建号；
- `rollback-target`：可验证的稳定回滚版本。

机器字段名：回滚版本使用 `rollbackVersion`（人读说明为“回滚版本”）；与 `version`、`buildId` 一起写入审计记录。

审计记录还必须包含紧急原因、操作者、任务号、版本/构建号、跳过的常规步骤、最低安全检查、回滚版本、发布结果、验证结果、固定执行顺序、UTC 时间、`auditId` 和 `idempotencyKey`。跳过项必须逐项列出，不得写成“常规流程已跳过”这一类笼统描述。

## 任务回写与历史兼容

回写使用发版任务的追加评论 `【紧急发版快车道】`，载荷 schema 为 `oneos.emergency-release/v1`。评论通过官方 CLI gateway 的 guard → action → verification 事务写入并回读；同一 `idempotencyKey` 重试只能复用既有成功回执。历史发版任务不要求补齐新字段，也不改历史描述、迭代字段、正式关系或既有尝试账本；只有本次快车道事件追加新评论。

脚本 `scripts/prepare_emergency_release.py` 默认只生成 `plan-only` 审计和回写计划。生成的计划需另由已有发布授权和 gateway 预检/应用流程执行；脚本自身不执行云效写入或生产发布。

## 禁止条件

何斐身份不匹配、任务 ID 不唯一、范围无法回读、版本/构建号缺失、回滚版本缺失、最低安全检查不完整，均阻断快车道。生产发布失败或验证失败仍沿用既有自动回滚/重新发布规则，不得用快车道直接重试生产。
