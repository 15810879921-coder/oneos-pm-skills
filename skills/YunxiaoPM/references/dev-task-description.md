# 【开发】任务描述（从需求 MD 精炼）

供**开发 Skill**在「分配任务 / 生成【开发】」时使用。产品侧 **YunxiaoPM 不创建**【开发】。

与 [settled-rules.md](settled-rules.md) 一致。

## 适用范围（强制）

| 需求类型（仅两种正式前缀） | 是否套用「修改前规则」 |
|---|---|
| **【优化】** | **是** |
| **【新增】** | **否**（短写或留空由开发 Skill 自定；仍禁止贴 MD/PRD 全文） |

判定：需求标题前缀或 AutoRDO **类型**字段。无第三种正式类型前缀。

## 原则（仅【优化】）

1. **输入**：需求 MD（优先 `## 原始诉求（AutoRDO）`；可辅以产品说明 / `requirements-prd.md`）
2. **输出**：精炼短描述；**禁止**全文灌入
3. **只写修改前的规则**：改之前怎么算、怎么拦、怎么展示；**简单关键**（通常 1～5 条）
4. **不写**：改后长文、验收清单、流程图、角色故事、原型长说明

## 推荐骨架（仅【优化】）

```markdown
## 修改前规则
- …
- …

（可选）完整说明见需求 / 交付：ONEOS-xx
```

## 示例

**正向（【优化】）**

```markdown
## 修改前规则
- 车辆氢费明细导入不做重复行校验，重复数据可直接入库
- 中英文括号不一致会拦截导入
```

**负向**

- 对【新增】套改前模板
- 粘贴整份 AutoRDO / PRD
- 把「修改后应如何」写成说明书

## 分工

| 工作项 | 描述 |
|---|---|
| 需求 | AutoRDO +（设计后）AutoPRD |
| 【交付】 | 设计完成后产品说明 / 原型链接 |
| 【开发】·【优化】 | 本文：修改前规则关键点 |
| 【开发】·【新增】 | 不适用本文 |
| 【交付】 | **不走本文**；调用 AutoRDO 写「修改前 + 修改后」规则对照章（`delivery-rules-chapter.md`） |
