# 知识准入评分

在每次调用的开始与结束各评估一次：开始时仅输出初判，结束时以完整证据作最终决定。分数由四项相加，满分 100；不确定时取较低分，不能因语言表述流畅而加分。

## 评分口径

| 维度 | 0 分 | 中间分 | 满分 |
| --- | --- | --- | --- |
| 通用性与稳定性（35） | 单次环境、平台状态或项目配置 | 已知同类场景可能复用，但边界不完整 | 跨同类后续任务稳定复用，且明确不适用范围 |
| 证据闭环（30） | 只有口述、标题或状态 | 有来源与部分复现/验证 | 来源、现象、根因、规避/修复、验证均可定位 |
| 可执行与可验证性（20） | 只有结论或建议 | 有检查方向但难以重复 | 有最小预防动作和明确验证方式 |
| 边界与冲突（15） | 适用范围不明或已冲突 | 有初步范围，仍有待确认项 | 范围、失效条件和冲突处理清楚且无已知冲突 |

## 硬门槛与处理

先检查硬门槛，再计算分数。命中任一项直接忽略：敏感信息；项目/工作区/平台快照；单个问题复述；无可定位来源；与实时仓库规则、任务材料或 confirmed 规则冲突；与任何既有 confirmed/candidate 相同或近似。

相同/近似检查按“现象、根因、预防动作、适用范围”四项比较：四项重合是相同，三项实质重合是近似。命中即不写入、不补充既有记录、不触发上传。

得分达到自动档时，先通过 GitHub 发布预检，再按 `retrospective-candidates.md` 的记录模型形成新的 `candidate`，并立即推送、读回。得分位于询问档时，不写任何文件，待何斐明确同意后仍须通过同一去重与 GitHub 同步门禁。忽略档不产生知识文件改动。

## 回执格式

```text
知识准入：初判|自动候选|待何斐确认|忽略
得分：通用性 x/35；证据 x/30；可执行 x/20；边界 x/15；合计 x/100
硬门槛：通过|不通过（原因）
处理：新增 candidate <ID>|补充 <ID>|待确认|未写入
GitHub 同步：未触发|已推送 <commit>|未落盘（原因）
```
