# 产品交棒快照

产品交棒快照是 PM 修改并确认 PRD、原型后留下的版本印记。它由 YunxiaoPM 生成和维护，开发侧只消费；不是开发分配时临时重做的需求分析。

## 生成时机

- `设计完成`：AutoPRD、原型、标注和交付规则写完后生成，随后写入需求和对应【交付】。
- `刷新产品快照`：产品在设计完成或交棒后再次修改 PRD/原型时执行；只替换快照受管区块，不改需求状态、交付状态、负责人、关系或迭代。
- 同一需求有 Web/小程序两条交付时，两条交付都必须回读快照。两端共用同一产品版本时可使用同一快照文件；范围不同则分别生成。
- 占位快轨没有 PRD/原型时允许无快照交棒，但必须明确`产品快照：缺失（占位交棒）`，开发侧只能按历史/占位兼容路径处理。

## 快照文件模板

```markdown
# 产品交棒快照

## 变更范围
- 本次新增/修改：...
- 明确不变：...
- 交付端：Web | 小程序 | 双端

## PRD版本
- 来源：<附件ID、文件或URL>
- 版本证据：<SHA-256；拿不到时记录读取时间、字节数/内容长度>
- 关键章节：<本次涉及的标题/锚点>

## 原型版本
- 入口：<index.html URL或文件>
- manifest：<URL/哈希；无则写未提供>
- annotation-source：<URL/哈希；无则写未提供>
- 版本证据：<构建号、提交、SHA-256或读取时间+长度>

## 页面与交互索引
- <端> / <页面或路由> / <默认、展开、弹窗、禁用、异常等状态>

## 验收入口
- <验收剧本、场景或章节锚点>

## 未决风险
- 无 | <尚未确认但不应被快照掩盖的事项>
```

文件至少 240 字并包含全部六个章节。原型不适用时可在`原型版本`写“不适用及原因”，但不能删除章节。拿不到底层材料哈希时保留来源、读取时间和内容长度；这不单独阻断。快照文件自身始终计算 SHA-256，并生成`ps-<哈希前16位>`快照编号。

## 云效受管区块

CLI 把同一快照写入需求和【交付】，只替换以下受管区块，区块外 AutoRDO、AutoPRD、规则对照、编号和人工内容保持不变：

```markdown
## 产品交棒快照
<!-- ONEOS_PRODUCT_HANDOFF_SNAPSHOT_START id=ps-... sha256=... -->
schema: oneos.product-handoff-snapshot/v1
快照编号: ps-...
需求: ONEOS-...
交付: ONEOS-...

<快照正文>
<!-- ONEOS_PRODUCT_HANDOFF_SNAPSHOT_END -->
```

写入必须经过`preflight-product-snapshot → apply-product-snapshot → read-back`。预检冻结需求、交付、状态、负责人、正式关系、原描述哈希和快照哈希；任一漂移时零写入并重新预检。apply 只更新描述并验证状态、负责人和`ASSOCIATED→需求`未变化。

## 开发侧新鲜度

开发任务记录产品快照编号和哈希：

- 哈希未变化：只精读本任务涉及章节、页面和交互状态。
- 哈希变化：重新裁剪开发任务快照并刷新技术方案。
- 产品快照内容揭示方案漏项：先补方案再开工。
- 老需求或占位交棒无产品快照：允许兼容补录，但必须标记，不能冒充 PM 已确认快照。
