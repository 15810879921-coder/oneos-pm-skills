# 无单快轨到待开发

适用：口令明确「快轨」或「推进至待开发」且当前需求尚无标准分析路径任务（或用户确认跳过分析）。

先读取需求 `交付端`；未给则停。

| 交付端 | 本步新建 |
|---|---|
| `Web` / `小程序` | **1** 套：【交付】+【设计】（对应端） |
| `共用服务` | **2** 套：Web 与小程序各建【交付】+【设计】；两条交付均 `ASSOCIATED→同一需求` |

## 动作表

| 对象 | 动作 |
|---|---|
| 需求 | 状态 → **待开发**；**预计工时=2**、**实际工时=2**（覆盖同日 8h 日历工时默认）；标签按口令；更新编号区块（含交付端与各端编号） |
| 【交付】 | 无则按上表新建；ASSOCIATED→需求（勿用 PARENT）；负责人均→何斐；**计划开始=创建当日**（`79`）；**不写**计划完成；**描述双路径**（见下）；**标签=需求模块标签 + 端侧标签**（Web 交付加 `Web`，小程序交付加 `小程序`；不得只用需求标签导致两端难辨）；更新编号区块 |
| 【设计】 | 每条端侧交付**必须各新建**一条；官方 CLI 创建 `PARENT→对应交付` 并回读（交付「子项」须可见）；**描述=复制需求当前描述正文**；计划开始/完成均=当日；任务→完成态；**标签与对应交付相同**（含端侧标签）；需要时再用 CLI 建立并回读 **ASSOCIATED→原始需求**；更新编号区块 |
| 【分析】 | **禁止创建** |

禁止：共用服务只建一条交付；单端却建两条。

## 交付描述双路径（A1）

| 口令/材料 | 【交付】描述 |
|---|---|
| **有手工/需求正文**（无指定原型） | **必须**调用 `$AutoRDO`，写入独立章节「规则对照（AutoRDO）」含 **修改前规则** + **修改后规则**（见 AutoRDO `delivery-rules-chapter.md`）；禁止只整文同步需求；禁止占位 |
| **指定原型页面** | `$oneos-autoprd` 可补充链接/产品说明；**仍须**含上述 AutoRDO 规则对照章 |
| 既无手工可同步正文、又无原型 | 才允许占位 `等待设计任务完成后自动填入`，Plan 勾选交棒占位风险，回报首行标红 |

有手工或原型时**禁止**交棒占位；有正文时**禁止**省略规则对照章。

快轨【设计】描述始终可复制需求当前描述正文；**与【交付】规则对照章分工不同**。

## AutoPRD

- 快轨默认可不跑 AutoPRD；**例外**：口令指定原型 → 交付走 AutoPRD 路径（上表）。
- 口令同时「设计完成 + 原型」时仍按步骤 4 灌需求产品说明段。

## 查重

只认任务编号。已有分析单不得因「快轨」被删除。

## 回报必含

- 需求 / 全部端侧交付 / 全部端侧设计编号（共用服务须回报 Web+小程序 两套）
- 「快轨：未建分析；设计已同步需求描述并当日收口」
- 交付端与交付条数：`Web|小程序→1` / `共用服务→2`
- 各端【交付】已打端侧标签（`Web` / `小程序`），与模块标签并存
- 交付描述来源：AutoRDO 规则对照章（修改前/后） / AutoPRD 补充 / 占位（若占位则首行标红）
- 需求预计工时=2、实际工时=2
- 设计关联项含需求编号；各端交付子项含对应设计编号
- 回报须确认各【交付】描述含 `## 规则对照（AutoRDO）` 两小节（非占位时）

## 与标准 / 编号直推对比

```text
标准：分析中→交付+分析 → 设计中→设计+收口分析 → 设计完成→收口设计 → 待开发交棒
快轨（无既有阶段单）：→ 待开发：新建交付+设计+交棒何斐（无分析；设计当日收口；需求工时 2+2）
编号直推：已有分析/设计编号 → 收口空计划完成 → 待开发+交付交棒（不新建冗余单）
```
