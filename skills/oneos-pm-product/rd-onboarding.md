# 研发 onboarding · 半页分诊卡（v1.4.71）

> **升档才读**：听众=研发，且题型=「怎么用 AI / 开 Agent / 合支规矩」或**本会话首次确认研发角色**。  
> 激活**禁止**默认读本文件。厚册：`src/resources/pm-methodology/ai-fullstack-dev-playbook.md`。

## 0. 两句话总纲

1. **能人 5 分钟改完的，禁止开 Agent。**  
2. **交给 AI 的，必须玻璃箱：意图 · 文件清单 · Diff 摘要 · 风险 · 验收证据；人 Review Diff 后再合入。**

## 1. 人机分诊（H0→Halt）

| 档 | 特征 | 谁干 |
|----|------|------|
| **H0** | ≤2 文件、≤20 行、意图无歧义 | **人改**（别开整段 Agent） |
| **H1** | 定位难、改动小 | 人定位 → AI 只出补丁方案 → 人改 |
| **A1** | 多文件、规则清、有复现与验收 | AI 改 + **强制玻璃箱** |
| **A2** | 范围大 / 产品口径风险 | **先 Plan** → 人确认 → 再 apply |
| **Halt** | 业财写库、发版、清库、无人确认直推 | **禁止无人确认直干** |

口头口令：`能不能人 5 分钟改完？能 → 别开 AI。不能 → 开 AI，必须 Diff + 验收路径。`

## 2. 一任务一支（硬闸）

> **一个云效任务 / 缺陷 ↔ 一条开发分支；未绑定不可合入集成分支、不可进发版。**

- 开发：`feature/<开发任务编号>` · 缺陷：`fix/<缺陷编号>`  
- 集成：前端 `develop` · 后端 `dev`（仓库实名以配置为准）  
- 合 Master / 发版：另走 `$yunxiao-master-merge-gate`（**不是**「完成开发」自动合生产线）

细则：`src/resources/pm-methodology/reply-dev-branch-release-gate-2026-08-13.md`

## 3. 玻璃箱五件套（A1/A2 必齐）

```text
① 意图复述（要修的是… / 不是…）
② 改动清单（路径 + 每文件一句）
③ Diff 摘要（行为前后；禁顺便重构）
④ 影响面 & 风险（未测什么）
⑤ 验收证据（怎么点绿；无证据不得说修好）
```

## 4. 明确禁止

- 简单 bug 仍开整段 Agent 装闭环  
- 野分支 / 未绑定任务就合入 / 进发版  
- AI 自 commit / 自 push / 绕过 Review  
- 聊天说「上线了」代替发版与测试证据  

## 5. 答复边界（分身强制 · 防刷屏）

| 场景 | 怎么挂本卡 |
|------|------------|
| 纯闲聊 | **不挂** |
| 只问门禁/能不能做（只要结论） | 法眼结论 + **一句**分诊指针（可链本卡，不甩半页墙） |
| 怎么用 AI / 开 Agent / 合支 / 本会话首次确认研发 | **挂本卡摘要**（§0–§2 即可）+ 链厚册 |
| 要投喂 Codex 的规程全文 | 升档厚册 playbook；本卡不够再扩 |
