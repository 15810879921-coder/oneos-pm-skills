# Codex任务分段索引与开发完成工作日志

## 1. 执行位置与结论边界

工时登记只在`完成开发:任务=<开发任务ID>`中收口，但任务归属索引必须在开发活动发生时增量记录，不得等到完成开发时全量扫描全部Codex会话。

工作日志处理顺序：

```text
确定实际开始和完成时间
→ 按开发任务ID查询增量分段索引
→ 通过Bug/MR/提交/分支和时间窗分层补查缺口
→ 仅深读轻量元数据命中的少量Codex任务
→ 自动完成唯一归属、排除冲突和去重
→ 汇总主动执行秒数并换算工时
→ 创建或更新唯一实际工时记录
→ 回读工作日期、实际工时、人员和工作描述
→ 保存审计证据
```

工时证据独立于代码交付和任务关单。任一取数、关联、精度或回读证据不可核验时，只跳过实际工时写入并记录`工时无可核验来源`；不得编造、不得要求开发人员选择会话或确认归属，也不得阻断已经通过代码交付和验证门禁的开发任务完成、测试范围判定或交接。

## 2. 精确开始与完成时间

1. 从当前开发任务、需求、分支、提交、MR创建记录和本次执行证据枚举全部适用交付版本；不要求代码资产关联成功。
2. 普通模式验证目标分支正确并取得已合并MR或已在集成分支中的唯一可信交付版本；隔离快速模式验证MR目标正确、无冲突、仅因评审门禁未合并，且远端源分支HEAD等于交付提交。
3. 普通模式优先读取各适用MR的可信`merged_at`并取最晚值；没有适用MR但存在唯一可信集成版本时，使用该集成版本的可信来源时间。隔离快速模式读取远端交付提交的可信提交时间。
4. 实际开始时间优先读取开始开发时保存的专用字段；无专用字段时读取首次`[开发开始]`评论或首次合法进入`处理中`的工作项动态。后续重试不得覆盖。
5. 按云效项目时区转换开始和完成时间，在实际工时记录的`工作描述`中同时保存精确到秒的两个ISO时间戳。
6. `工作日期`只保存自然日期：`gmt-start=实际开始日期`、`gmt-end=实际完成日期`；不得用日期值冒充精确时间。

禁止使用当前命令时间、流水线时间、第一条MR合并时间或手工估算时间替代。开始或完成时间缺失时不得补造，只跳过工时登记。

## 3. 增量任务分段索引

### 3.1 记录时机

`开始开发`、`开发任务`、`提交代码`、`完成开发`、单Bug修复、批量开发和批量Bug处理在取得唯一开发任务上下文后，都应自动维护`oneos.codex-task-segment/v1`索引。开发人员不需要使用标准命令、不需要选择会话，也不需要确认匹配结果。

任务上下文首次建立时开始一个分段；发生下列任一变化时关闭旧分段并开始新分段：

- 当前云效开发任务或正式关联Bug发生变化；
- 切换到另一任务正式绑定的仓库、分支、MR或提交；
- 开始读取或修改另一任务指纹范围内的材料、页面、接口或代码；
- 当前工作转为公共排障、非开发事项或与任何任务都无法唯一关联的内容；
- Codex任务结束、暂停或进入等待用户/审批状态。

每条索引至少保存：

```text
schemaVersion=oneos.codex-task-segment/v1
Codex任务ID
分段ID
开发任务ID
需求ID/交付任务ID/正式关联Bug
仓库/分支/MR/提交
分段开始/结束检查点
平台主动执行秒数或可定位的时长字段
自动关联依据
记录时间
```

索引是本地审计数据，不写入业务描述，不保存凭据、Cookie、对话全文或生产数据。更新同一`Codex任务ID + 分段ID`时必须幂等，禁止重复累计同一时间区间。

所有索引动作通过本Skill自带适配器执行：

```text
skill-run codex_task_time.py upsert-segment --development-task-id <DEV-ID> --thread-id <Codex任务ID> --segment-id <分段ID> --started-at-ms <毫秒> --ended-at-ms <毫秒> --active-seconds <秒> --disposition linked|excluded|unassigned --evidence <依据>
skill-run codex_task_time.py resolve --development-task-id <DEV-ID>
```

同一分段重试使用相同`thread-id + segment-id`，适配器只更新原记录，不新增重复工时。`excluded`和`unassigned`分段保留审计记录但不进入工时汇总。

### 3.2 索引载体与取数接口

优先使用Codex运行时提供的任务/回合元数据和结构化本地状态；运行时应把索引保存在当前用户的Codex状态目录，而不是业务仓、Skill安装目录或云效描述中。索引文件按开发任务ID建立可直接查询的键，原始会话正文不进入索引。

取数接口至少必须提供：

```text
列出当前及历史任务的轻量元数据
按Codex任务ID读取回合列表
读取回合started_at/completed_at/duration_ms或等价字段
识别归档状态但不默认加载归档正文
按任务ID、Git资产和时间范围过滤
```

若运行时使用本地数据库，先做只读能力探测并核对表/字段存在，再读取任务表中的`id/title/目标/created_at/updated_at/archived/git_branch/git_sha/git_origin_url`和回合表中的`thread_id/turn_id/status/started_at/completed_at/duration_ms`或等价字段。禁止依赖未经探测的固定数据库路径或静默猜测字段；不支持这些能力时记录具体缺口，不通过扫描全部原始会话文件补偿。

本Skill的标准能力探测和定向发现入口为：

```text
skill-run codex_task_time.py probe-codex
skill-run codex_task_time.py discover --started-at-ms <实际开始毫秒> --completed-at-ms <实际完成毫秒> --anchor <开发任务/正式Bug/MR/提交/分支锚点>...
```

`discover`只返回轻量任务/回合定位和需要定向深读的Codex任务ID，不输出会话正文；能力探测或字段校验失败时退出，不退化为全量文件扫描。

### 3.3 任务指纹

每个开发任务从云效和代码事实自动形成任务指纹：

```text
开发任务ID、需求ID、交付任务ID、正式关联Bug
正式关联的仓库、分支、MR、提交
技术方案涉及的模块、页面、接口、业务字段和预计修改文件
```

标准命令中的开发任务ID只是最强锚点之一，不是唯一入口。不按命令执行时，仍应从当前云效操作、Git/Codeup资产、文件范围和业务材料自动维护指纹与分段。

## 4. 自动关联与冲突处理

关联优先级固定为：

```text
正式云效/Git关系
> 精确开发任务ID或正式Bug关系
> 唯一分支/MR/提交关系
> 无冲突的代码范围与技术方案组合证据
> 单纯业务语义
```

具体规则：

1. 正式关系或精确ID唯一命中时，自动归属对应开发任务。
2. 没有精确ID时，只有任务指纹中的仓库/代码资产与材料范围组合后唯一指向一个开发任务，才自动归属。
3. 相同标题、同一负责人、同一需求、同一仓库、相似业务文案或公共文件单独出现时，不足以归属。
4. 一个Codex任务只处理一个开发任务时，可统计其全部有效主动执行时长；混合会话必须按分段分别归属。
5. 一个分段同时被多个任务以同优先级命中、一次公共操作无法拆分、或分段边界无法核验时，系统自行标记`未归属`，不写入任何任务、不重复分摊，也不要求开发人员确认。
6. Bug分段只有在云效正式关系证明该Bug属于当前开发任务时才能计入；不能按标题或代码相似度代替正式关系。

归属结果只有`已归属`、`排除`和`未归属`三种，不生成需要开发人员处理的候选清单。

## 5. 完成开发时的分层查找

完成开发不得默认全量读取所有Codex会话。固定按以下顺序查询，命中后逐层补齐，禁止为追求零遗漏无界扩张：

1. **精确索引查询**：按当前开发任务ID读取所有`oneos.codex-task-segment/v1`记录。
2. **代码资产反查**：按正式关联Bug、MR、提交和分支查找已索引分段。
3. **时间窗元数据查询**：仅在实际开始至实际完成时间范围内，读取Codex任务标题、目标、任务ID锚点、仓库、分支、MR和提交等轻量元数据；同时覆盖可由索引或元数据命中的归档任务。
4. **定向深读**：只读取上一步命中的少量Codex任务的消息和工具事件，自动重建缺失分段；不得先加载全部会话全文。
5. **停止条件**：以上来源仍无法唯一归属的内容标记`未归属`并结束查找。正常完成开发流程禁止退化为全量会话深读；全量重建只能作为独立的索引修复任务执行。

最终保存扫描范围和结果：索引命中数、元数据命中数、深读任务数、已归属/排除/未归属分段数，以及每个已计入分段的证据。不得向开发人员发起会话选择或归属确认。

## 6. 主动执行时长口径

优先读取Codex平台任务、回合或目标元数据提供的主动执行时长字段，例如可信的`duration_ms`或等价秒数。它应覆盖模型推理、工具执行和当前开发分段内的有效处理时间。

不计入：

- 等待用户输入、验证码、审批或外部人员评审的空闲时间；
- 任务暂停、归档后无人操作的时间；
- 与当前开发任务无关、已排除或未归属的分段；
- 已在其他分段计入的重复时间区间。

不得用首条消息到末条消息的自然时间差代替主动执行时长。一个平台回合同时混合多个任务且没有可核验的内部检查点时，该回合标记`未归属`，不得按消息数、文件数或主观比例分摊。

## 7. 分钟和小时换算

先汇总全部去重后的原始秒数，再统一换算，不能逐任务先四舍五入：

```text
总秒数 = Σ每个已归属有效分段的主动执行秒数
总分钟数 = max(1, floor((总秒数 + 30) ÷ 60))，仅在总秒数>0时
未舍入小时 = 总分钟数 ÷ 60
计算工时 = 未舍入小时按HALF_UP保留2位小数
云效记录工时 = 写入计算工时后的接口回读值
```

云效实际工时接口单位必须确认是小时。若项目字段按固定精度确定性归一化，例如`0.28 → 0.3`，在同一工作描述中同时保留`计算工时`与`云效记录工时`，并以回读值核对工作项汇总。单位不明、回读不稳定或无法解释时跳过对该工时记录的采信并报告缺口，不阻断开发任务关单。

## 8. 工作日志写入和审计

先通过`projex-list-effort-records --id <开发任务内部ID>`读取现有记录。以`项目ID+开发任务ID+complete_time_accounting`为幂等键：没有匹配记录时调用`projex-create-effort-record`，已有唯一匹配记录时调用`projex-update-effort-record`，多条匹配时停止工时写入但继续已通过其他门禁的开发关单。

固定写入：

```text
id/workitem-id = 当前开发任务内部ID
operator-id = 当前开发任务负责人用户ID
gmt-start = 实际开始时间的项目时区日期
gmt-end = 实际完成时间的项目时区日期
actual-time = 换算后的两位小数计算工时
description = 结构化开发完成统计
```

`description`至少保留：

```text
[开发完成统计]
开发任务=<DEV-ID>
适用MR/交付版本及来源时间=<列表>
实际开始时间=<项目时区ISO时间>
实际完成时间=<项目时区ISO时间>
Codex任务/分段=<去重列表>
查找范围=<索引/代码资产/时间窗/定向深读摘要>
分段结果=<已归属/排除/未归属数量>
总秒数=<整数>
总分钟数=<整数>
换算=<总分钟数>/60=<未舍入小时>
计算工时=<两位小数小时>
云效记录工时=<接口回读小时>
幂等键=<项目ID+开发任务ID+complete_time_accounting>
统计时间=<ISO时间>
```

写入后重新读取实际工时明细，核对记录ID、人员、工作日期、小时和完整工作描述。平台确定性归一化时，先把回读值补入同一记录的工作描述，再次回读并核对工作项`实际工时`汇总；不得新增第二条记录。任何回读不一致、部分成功、幂等键重复或人员错误都使本次工时证据无效，记录缺口并跳过采信，但不回滚可信代码交付、不阻断当前开发任务关单或测试交接。
