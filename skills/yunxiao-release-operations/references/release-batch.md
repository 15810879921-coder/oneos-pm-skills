# 准备发布的范围冻结与A/B/C/D

## 入口

```text
/skill yunxiao-release-operations
准备发布：迭代=<精确名称>
```

项目从迭代反查，不接受手工项目覆盖。迭代只正式挂载`【交付】`：需求不需要直接关联迭代；只要`【交付】`正式属于该迭代且`ASSOCIATED→需求`有效，即视为该迭代正式需求。默认不要求需求编号：系统读取这条关系链中的全部需求，自动选入非延期且状态为`测试完成`的项。`需求=<REQ-ID,REQ-ID,...>`仅作为热修复、灰度或明确局部发布的覆盖入口；提供时必须非空、无重复、可由本迭代交付唯一反查。

## 分类

先冻结迭代全部正式需求快照，再运行：

```powershell
skill-run classify_release_scope.py --input scope.json
```

分类含义：

- A：默认自动选入的`测试完成`需求（或局部发布时显式选入项），属于该项目，且可经“本迭代`【交付】`→`ASSOCIATED`需求”唯一反查，关联【测试】=`已完成`。进入发布范围。
- B：属于迭代但已正式延期，或默认自动范围下尚未达到`测试完成`的需求。记录为下一批候选，不阻塞本批。
- C：仅局部发布时显式选入但需求或关联【测试】尚未完成的需求。阻塞本批。
- D：跨项目/跨迭代、迭代交付到需求的正式关联缺失、同一需求同时选入和延期、编号不存在或范围冲突。阻塞本批。

测试部署、QA证据、用例执行和缺陷闭环仅作为发版任务内的可选记录，不参与`准备发布`的A/B/C/D阻断判定。每条需求只需携带`testTaskId`及其实际状态；可用的测试记录应原样摘要到发版任务中，但缺失、环境不一致、用例未执行或缺陷未闭环均不得阻止准备发布。

项目不一致、迭代交付关系不一致、需求关联缺失或范围冲突归D类；需求或关联测试任务未完成归C类。

只有`A非空 && C为空 && D为空`时才允许写云效。

## 创建顶层【发版】任务并冻结范围

通过后：

1. 以命令中的精确迭代为唯一关系起点：读取该迭代已挂载的全部源`【交付】`，通过每条交付的`ASSOCIATED→需求`关系确定本批需求；B类或其他范围的交付只记录，不关联到本次发版。读取同一迭代的Bug（以Bug迭代字段或可验证的正式关系链为准）；仅当Bug真实状态为`已完成`或`已关闭`且未正式关联任何`【交付】`任务时，才列为“无交付已完成Bug”。不得扫描或混入其他迭代/项目的Bug。
2. 在迭代内按`项目ID + 迭代ID + 排序后的A类需求ID + 排序后的无交付已完成BugID + release_prepare`生成幂等键和范围哈希。
3. 创建或复用唯一顶层`【发版】<迭代>-<批次摘要>`任务；它的层级必须高于【交付】，不得以`TASK_SUB`挂到任何【交付】下。
4. 正式关联发版任务、该迭代、A类需求、从该迭代和A类范围派生的多个源【交付】和已完成【测试】任务；同时正式关联全部同迭代的无交付已完成Bug。一个发版任务可关联多个交付任务，交付任务不成为发版任务的父节点。
5. 在发版任务描述中写入受管范围区块：A/B/C/D快照、可读取的测试记录摘要、源交付任务清单、无交付已完成Bug清单、生成时间、范围哈希和幂等键；保留人工内容。
6. 同时冻结生产流水线、环境、负责人、审批、窗口、回滚方案和生产验证计划；缺失或不唯一时零写入。
7. 回读发版任务顶层关系、项目、迭代、A类需求、源交付、测试任务、无交付已完成Bug、范围区块和生产验证计划。B类仅记录，不建立本批发布关系；不把测试证据完整性作为回读通过条件。
8. 复用发版任务时，必须回读顶层关系和全部受管关联；若尚无任何生产尝试，可补齐缺失的应有关联后回读；已有生产尝试、存在`TASK_SUB→【交付】`父子关系、范围/关联冲突或任务不唯一时阻塞，不重挂或扩容历史任务。
9. 范围已冻结的发版任务不得因后来新增的测试完成需求或新关闭Bug自动扩容；范围不一致时阻塞并说明差异。
10. 返回`发版任务ID`，下一条固定为：

```text
/skill yunxiao-release-operations
执行发布：发版任务=<发版任务ID>
```

重复命令必须复用同一任务；存在多条相同幂等键任务时阻塞，不自动选最新。
