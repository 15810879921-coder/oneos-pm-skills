# 关闭 / 归档迭代

## 输入与前置

口令：`关闭迭代：迭代ID=…`。先以 `projex-get-sprint` 回读迭代名称、状态、起止日期、负责人和 ID；状态已为 `ARCHIVED` 时直接幂等回报。仅当迭代内事项全部完成，才可继续；未完成事项必须逐项列出并停止，禁止强关。

## CLI 优先与接口核验

1. 先检查 `aliyun devops --help` 及 `projex-*sprint* --help`，确认是否存在“开始 / 完成 / 归档迭代”的状态动作；`projex-update-sprint` 仅可更新名称、日期、负责人、工时容量等字段时，不得把它误当作归档接口。
2. 若可用，在浏览器开发者工具 Network 中完整观察页面操作，从“开始”到“完成迭代”最终确认，记录请求方法、路径、请求序列和响应结果；禁止只观察首次悬停或第一次点击就断言接口。
3. 官方 CLI 存在等价状态动作时，只走 CLI；没有等价动作时才进入下节视觉兜底。浏览器无法读取 Network 时，不得杜撰接口名或请求体，只记录已验证的页面流程和 CLI 缺口。

## 受控视觉兜底（仅 CLI 缺口）

1. 定位指定迭代卡片，核对名称、负责人、日期、完成度和状态，防止误操作。
2. `TODO/未开始`：悬停状态后点“开始”，在“开始迭代”弹窗核对开始、结束日期，再确认。
3. `DOING/进行中`：悬停状态后点“完成”，在“完成迭代”弹窗核对“所有事项已完成”的提示与结束日期，再作最终确认。
4. 每次状态变更后重新读取页面；最终确认后使用官方 `projex-get-sprint` 回读，只有 `status=ARCHIVED` 才可报告成功。
5. 任一弹窗出现未完成事项、日期异常、权限失败或页面状态未刷新时，停止并报告；不替换日期、不跳过警告、不点击删除/锁定等相邻图标。

## 回报

回报迭代名称、ID、操作前后状态、CLI 缺口结论、实际执行路径（CLI / 视觉兜底）、页面确认结果和 `projex-get-sprint` 的 `ARCHIVED` 回读证据。不得把页面列表消失单独作为成功证据。
