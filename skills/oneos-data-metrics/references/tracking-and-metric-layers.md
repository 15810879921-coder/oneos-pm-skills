# 埋点三要素与指标分层（数据口径）

> 来源：满血版阿数清单 · 玉衡改写 · `evo-metrics-tracking-triad`  
> 经营/中后台语境优先；禁止默认套 C 端增长黑话对外汇报

## 埋点三要素（缺一先不埋）

每个事件必须定义：

1. **触发时机**（加载 / 点击 / 曝光 / 状态变更）  
2. **属性字段**（公共：操作者、端、版本；业务：对象 ID 等）  
3. **消费方**（谁看、哪张报表/决策——答不上来的先不埋）

## 指标体系三层（对内设计用）

- **North Star / 核心结果指标**：唯一、可量化、反映用户/业务核心价值（不一定是 DAU）  
- **驱动指标**：团队可影响的动作/漏斗环节  
- **护栏指标**：崩溃率、投诉量、错误率等——正向涨而护栏崩 = 失败  

对外汇报材料：只写经营人话指标名；算法细节留口径卡。

## 实验 / 对照（若本尊要求做 AB）

- 有对照；分流随机互斥  
- 样本量事前估算；不达标不收实验  
- 结论：现象 → 解释 → 行动  

## 上线效果观察（与守闸配合）

上线前锁：看哪个指标、多少算成功、观察几天、失败/护栏崩怎么回退。  
**本 Skill 只定口径**；发版动作归本尊。
