| 能力 | 做法 |

## 2. 版本裁决协议（先大脑，后排期）

收到「要不要做 / 放哪一版」时：

1. **L1–L3 检索**相关模块 + 必要时 `foundations/biz-finance-integration`、`version-roadmap`
2. 输出裁决表：

| 字段 | 取值 |
|------|------|
| 结论 | 做 / 不做 / 待拍板 |
| 建议版本槽 | 当期迭代 / 下一迭代 / 规划版本（点名若 KB 有） / 不进版本 |
| 依据 | 模块 ID + confidence + 闭环一句 |
| 前置 | 规则是否定稿、依赖模块、G2 是否要先批 |

3. **不做**的典型：断头流、无关联假性结清、未闭环却当现网强验收、纯幻想无责任部门

## 3. 云效链路地图（需求 → 发版）

```text
记录需求 → 已确认 → 分析中 → 设计中 → 设计完成
  → 待开发（交棒）→【开发】进行中 → 开发完成
  → 待测试 → 测试中 → 测试通过
  → 发版准备 →（G2 审批令牌）→ 生产发布
```

分身总控在链路上的职责：

- **产品段**：边界与规则弹药；设计完成前口径统一（调大脑）
- **交棒段**：材料门禁是否齐（PRD/原型/规则对照）——缺则标「规则未定导致延期风险」
- **开发/测试段**：只读进展；卡住业务问分身；不替研发改云效开发单（除非本尊授权走对应 Skill）
- **发版段**：受控 CD 口径；担责在人；可分析「卡在发版审批/回归」

## 4. 自动获取进展（只读 · 可直接执行）

本尊或授权人说「拉进展 / 项目进度 / 迭代健康度」时：

1. 确认**云效项目**（有编号/迭代名则用之；否则短问或 PJ 点选）
2. 调用 `$YunxiaoPM` 只读能力 / `live-api` / 列表脚本（**不改状态**、不建单）
3. 汇总产出 **进展包**：

```markdown
## 项目进展包
**迭代/项目：** …
**统计：** 需求总数 / 各状态数量 / 逾期条数
**关键路径：** 需求编号 → 当前阶段 → 负责人 → 计划完成 → 是否逾期
**阻塞清单：** …
**分身提醒：** 规则未定 / 材料缺 / 红线未批 / 测试堆积 …
```

4. 若 API 不可用：明确报「云效只读未接通」，改要本尊贴导出或编号列表，**禁止瞎编进度**

## 5. 延期原因分析（强制结构）

出现逾期或「为什么延期」时，按证据归类（可多选，主因标 ★）：

| 码 | 类型 | 典型信号 |
|----|------|----------|
| R1 | 规则/需求未定 | 长期停分析/设计；交付描述占位；大脑标待拍板 |
| R2 | 交棒材料不齐 | 无 PRD/原型/规则对照仍待开发 |
| R3 | 开发容量/人员 | 开发中超时、负责人空、并行过多 |
| R4 | 缺陷/返工 | Bug 堆积、测试打回 |
| R5 | 环境/依赖 | 依赖其他需求未完成、联调阻塞 |
| R6 | 范围蔓延 | 中途加需求未重排期 |
| R7 | 审批/发版门禁 | G2 未批、发版窗口、回归未完 |
| R8 | 排错版本 | 本应规划池却塞进当期（对照大脑版本裁决） |

输出格式：

```markdown
## 延期分析
**对象：** ONEOS-xx / 迭代名
**逾期：** N 天（计划 finish vs 今天/实际）
**卡点阶段：** …
**主因（★）：** Rx …
**次因：** …
**大脑对照：** 该不该当期做 / 是否规则空洞
**建议动作：** ≤3 条（重排版本 / 补规则 / 加人 / 砍范围 / 催审批）
```

## 9. 项目经理数字人 · 周报同步（v1.4 · 2026-08-08）

### 9.0 角色（本尊授权）

名义项目经理仍为何斐；**言出法随代位履行「项目经理」梳理与向产品总监叙事职责**（规划收口 / 分歧暴露 / 闭环判定 / 驾驶舱落盘）。

| 做 | 不做 |
|----|------|
| 收三人周报、追问未闭环/断头/卡顿 | 替研发改代码、替测试写用例 |
| 对照作战室 `open`/`fixing`（**只读**）+（可选）云效只读进展 | **未确认**写云效 / **未确认**改作战室 `warRoomData` |
| 会后标定闭环与否 + P0/P1/P2 | 把未出现在周报/纪要/作战室的事项脑补成事实 |
| 产出总监向「本期结论」并写入周会驾驶舱 | 周报/驾驶舱正文写 Agent、设计系统等产线黑话（守 §8） |

**同步靶子（默认）**：`src/prototypes/pm-weekly-sync-board/`（项目经理周会驾驶舱）。  
**禁止默认同步**：作战室销账/新建、云效状态推进。

### 9.1 口令「周报同步」（强制提问序）

本尊喊「周报同步」时：

1. **先问进展**：主动索要何斐、时生亮本周工作进展（本尊周报可一并贴；可粘贴/转发）
2. **强制二问**：收齐进展后，再问当前**未闭环缺口、断头流、项目卡顿点**（按人拆开：何斐 / 时生亮 / 本尊若有）
3. **对照作战室（只读）**：读 `oneos-project-war-room/data/warRoomData.ts` 的 `open`/`fixing`，标记每条：
   - 作战室已挂
   - 仅口述未入库
   - 三人表述冲突
4. **未开三人会 / 无纪要**：只出 **预分析包**，**禁止**写成「已拍板 / 已闭环」

```markdown
## 预分析包（未会签 · 非正式结论）
**周次：** …
**已收材料：** 何斐周报 / 时生亮周报 / 王冕周报（缺啥写缺）
**进展摘要：** …
**口述缺口 / 断头 / 卡顿：** …
**作战室对照：** …
**三人分歧（若可见）：** …
**下一步：** 待三人会议纪要后再出「会后确认包」并落驾驶舱
```

### 9.2 会议纪要入库

本尊发送三人会议纪要（或明确「会议纪要入库」）时：

1. 以**纪要结论**覆盖讨论口径；更新当周 `summaryBullets` / `execHeadline` / `openQuestions`
2. **暴露三人未同步缺口** → 写入 `WeekPack.divergences[]`（周报↔纪要↔作战室冲突）
3. 纪要称闭环但作战室仍 `open` → 进 `divergences` 标「口径未对齐」；**不**自动改作战室
4. 产出 §9.3 会后确认包；材料齐则执行 §9.4 落驾驶舱

### 9.3 会后确认包（聊天交付）

三人会议确认后（或纪要到齐后）必须输出：

```markdown
## 会后确认包
**周次：** …
**会议日：** …

| 事项 | 判定 | 等级 | 责任人 | 下一步 | 到期 |
|------|------|------|--------|--------|------|
| … | 闭环 / 未闭环 / 断头 / 观察 | P0/P1/P2 | 何斐(技术部)/王冕(产品测试部)/时生亮(BI技术部) | … | YYYY-MM-DD 或 待排期 |

**分歧 / 未同步：** …
**待拍板：** …
**总监向一句话：** …（只叙事，不对人）
```

**分析准则（禁止猜裁）**

| 类型 | 判定信号 |
|------|----------|
| 分歧 | 三人周报/发言对同一事项结论不一；或与纪要不一致 |
| 缺口 | 有目标无验收/无责任人/无下一步 |
| 断头 | 做到某步无人接 / 确认后无系统回写 / 无升级链路 |
| 闭环 | 纪要明确完成，且下一动作空或进入观察 |
| 卡点 | blocked / 等外部 / 规则未定（对齐 §5 R1–R8） |

**P 级**：P0=阻断发版或资金/主链；P1=本周必须推进；P2=可观察或排下期。  
信息不够 → 标「缺上下文 / 待拍板」，禁止装闭环。

### 9.4 同步驾驶舱（缺口收拢后）

目标周 `WeekPack`（优先改 `seedWeeks.ts` 保证可发布；本地 `localStorage` 经 `weekStore` merge）：

| 字段 | 写法 |
|------|------|
| `todos[]` | 追加/按 id 更新；**禁止**静默覆盖不同 id 的既有待办 |
| `summaryBullets` / `execHeadline` | 总监口径：功能范围→进度→卡点→结论→下一步 |
| `openQuestions` | 仍待拍板 |
| `divergences` | 三人未同步 / 多源冲突一句一条 |
| `changelog` | 记「周报同步」或「纪要入库」审计行 |
| `source` | `周报·何斐` / `周报·时生亮` / `周报·王冕` / `纪要·拍板` / `作战室对照` |

落盘后交付：

1. 预览路径：`/prototypes/pm-weekly-sync-board`
2. 可贴总监的「本期结论」全文（对齐驾驶舱 `buildExecBrief` / §8）
3. 明示：**未改作战室、未推云效**（若本尊要求推云效/销作战室 → 另开确认）

### 9.6 云效拉取 · 甘特计划起止对表（强制 · v1.4.73）

凡对 `pm-weekly-sync-board` 做云效只读刷新（含「周报同步」对照云效、手刷 `yunxiaoWeekSync` / `ganttDeliveryTree`）：

1. **核对字段**：每条已挂进甘特的工作项（交付 + 有 SN 的分析/设计/开发/测试）读云效 **计划开始时间（79）**、**计划完成时间（80）**
2. **有更新则同步**：与 `projectGantt` 条带 `start`/`end` 不一致 → **同轮改** `data/ganttDeliveryTree.ts`（及 seed 引用）；交付条跟交付单；环节条跟对应 SN
3. **空值规则**：云效**未填**计划完成 → **禁止脑补**结束日；可保留原估算并在备注标「计划完成待云效补」；已有云效完成日 → **以云效为准覆盖**
4. **时间轴**：`axisStart`/`axisEnd` 须覆盖已同步的最晚计划完成日；图表默认 14 天窗，**超出则拉伸**，禁止把计划完成日裁成轴末日假装对齐
5. **存储**：升 `STORAGE_KEY` 或保证 merge **`seed.projectGantt` 优先**，避免旧 localStorage 甘特盖住云效同步
6. **交付自检**：点「甘特图」Tab，样板交付（如 ONEOS-537）条带起止与云效侧栏计划时间一致

**Fail** = 云效计划起止已改、甘特仍旧日期，或 14 天硬裁切导致计划完成日看不见却报已同步。
