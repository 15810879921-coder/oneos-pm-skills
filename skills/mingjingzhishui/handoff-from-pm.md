# 明镜止水 · 交棒包消费（handoff-from-pm）

> **升档才读**：收到交棒、校验缺项、拒收、写回执时。  
> 激活禁止默认读。配对言出法随 [`../yanchufasui/handoff-to-dev.md`](../yanchufasui/handoff-to-dev.md)。

## 0. 硬闸

**唯一合法输入** = 言出法随交棒包（或本尊粘贴的同 schema 文本）。  
聊天碎片 / 口头一句「做个某某」**不算**交棒 → 拒做并列出缺项。

## 1. 交棒包 schema

```markdown
## 明镜止水交棒包
- 需求编号：（ONEOS-xx / 无则写「无编号」）
- 波次 / 进化任务 ID：（如 P0 / evo-xxx · **必填**）
- 原型 id：（oneos-v2 目录名 / 新建则写拟用 id）
- PRD 路径：（如 `src/prototypes/{id}/.spec/requirements-prd.md`）
- 一句话目标：
- 范围 · 做：
- 范围 · 不做：
- 用户故事：（起点 → 运作 → 闭环；可多条）
- 验收 · 正路径：
- 验收 · 逆路径：
- 验收 · 门禁：
- 自检记录：（必点 URL + 已点绿项；波次收口必填。**不是**测试「通过」）
- 视觉锚点：（可选；现网 URL / 截图路径 / 须对表控件清单；壳·登录·台账像素对表类**建议填**）
- 轨指令：A_only | A_then_B | B_only
- 真仓锚点：（可选；模块路径 / 现网 URL / 子仓名）
- 页面或接口路径：（氢/能/跨库**必填**；如 `/asset/hydrogen/ledger` 或菜单名）
- 已知缺口 / 待拍板：（无则写「无」）
- 本尊确认轨指令：（是 / 否；B_only 必须是）
```

### 必填

| 字段 | 拒收条件 |
|------|----------|
| 波次 / 进化任务 ID | 空（口语「这一刀」不算） |
| 一句话目标 | 空或含糊到无法验收 |
| 范围 · 做 / 不做 | 缺任一侧 |
| 用户故事 | 缺，或无「闭环」 |
| 验收 · 正路径 | 缺 |
| 验收 · 逆路径或门禁 | 两者都缺 |
| 自检记录 | 波次勾齐 / P0 收口类任务缺清单 |
| 轨指令 | 缺或不在三选一 |
| PRD 路径或可粘贴的完整 PRD 正文 | 两者都无 |
| 本尊确认轨指令 | `B_only` 时不为「是」 |
| 页面或接口路径 | 范围含氢/能/跨库（asset 与 energy 双库），却无菜单入口也无 `/asset` `/energy-v2` `/energy` 前缀 |

### 选填

- 需求编号、原型 id、真仓锚点、已知缺口、**视觉锚点**  
- 页面或接口路径（非跨库任务可空）  
- **视觉锚点**：交棒写「像素对表 / 壳 chrome / 冻结列 / 登录主题」却无锚点 → **不拒收**，但回执须标 `deviationCode: visual` 或待拍板「缺视觉锚点」

## 2. 校验流程

```text
收到交棒
 → 按上表勾必填
 → 有缺 → 输出「拒收 · 缺项清单」；禁止写代码
 → 齐全 → 复述轨指令 + 本轮只做哪一轨
 → 开干前再扫一遍「待拍板」：非空则先问本尊是否带病开工
```

## 3. 轨指令语义

| 值 | 行为 |
|----|------|
| `A_only` | 只改 `oneos-v2`；交付可点原型；不进 `oneos-prod` |
| `A_then_B` | 先 A；A 通关后**停**，等本尊点头再 B |
| `B_only` | 跳过原型直进真仓；须交棒写明本尊确认=是 |

## 4. 回执模板（消费后强制）

```markdown
## 明镜止水 · 交棒回执
- 交棒校验：通过 / 拒收（缺项：…）
- 波次 / ID：（与交棒一致）
- 当前轨：A | B | 等待点头进 B
- 已实现：（**逐条对照自检记录**；禁止只写「做完了」）
- 偏差：（无则「无」；有则写清与交棒差异，禁止暗改）
- 待拍板：（本轮新发现；无则「无」）
- 证据：预览路径 / http://127.0.0.1:5666 + 必点清单
- 下一步：
```

正文后**建议**再附机器块（语言标记必须为 `mj-receipt`）：

```mj-receipt
waveId: P0
taskId: evo-mj-xxx
track: A
passed: true
evidencePath: src/prototypes/…/.spec/handoff-mj-….md
deviationCode: none
nextWave:
nextAction: wait_pm_b
```

### 4b. 波次勾齐硬闸

- **无**「波次收口 / P0 证据包」交棒 → **禁止**自改作战室 `dualTrackProgress` 的 proto/prod 为齐  
- 回执「已实现」必须点名对照哪条通关（如 P0 证据包 1/2/3）；装闭环 = Fail

### 4c. `mj-receipt` 机器字段（v1.0.10 · 作战室半自动）

| 键 | 取值 | 说明 |
|----|------|------|
| `waveId` | `P0`…`P7` 或空 | 与交棒波次一致；进化任务可只填 `taskId` |
| `taskId` | `evo-mj-…` | 进化任务 ID |
| `track` | `A` / `B` / `A_then_B` / `wait_B` | 当前停在哪 |
| `passed` | `true` / `false` | 本轮自检记录是否对照齐；拒收=false。**不是**测试验收「通过」 |
| `evidencePath` | 仓内相对路径 | 交棒包或回执所在 md |
| `deviationCode` | 见下表 | `none` 才能被脚本优先抬「通过」 |
| `nextWave` | `P1`… 或空 | 回执写「下一步 Pn」时填 |
| `nextAction` | 见取值列 | 给人话下一步；脚本可忽略 |

**deviationCode**

| 码 | 含义 | 下一棒 |
|----|------|--------|
| `none` | 无偏差 | 可等点头进 B / 结束 |
| `scope` | 范围不符 | 言出法随改包 |
| `acceptance` | 验收条对不上 | 言出法随改包 |
| `runtime` | 本机工程阻塞 | 明镜建议解阻；不装通关 |
| `visual` | 像素/壳对表缺口 | 补视觉锚点或改包 |
| `await_pm` | 待本尊拍板 | 拍板后改包再交 |
| `conflict_kb` | 与 KB/现网口径冲突 | **升法眼** → 改包 |

有偏差或待拍板 → 同轮贴 [`twin-linkage.md`](twin-linkage.md) §2c「请言出法随改包再交」。

## 5. 与法眼交棒码的关系

法眼 W/S/C/B 是给**言出法随**收口用的。  
明镜侧**不**代替写作战室评分；若本尊要求同步作战室，回执里写「请言出法随落 W/S/C」，或本尊点名后明镜再动 war-room。  
**轨 B 现网冲突**：回执 `deviationCode: conflict_kb`，升法眼，禁止自行改交棒语义。
