## 已修复

1. **接收测试任务不再重复产品交棒流程。** `yunxiao_cli_test_lifecycle.py start` 只要求对象、正式关系、当前状态和测试范围一致，写前重新核对，写后官方回读。不加载产品 bundle，不要求迭代/部署区块，不改任务描述。输出明确提醒：接收不等于实际测试或测试通过；实际执行前仍需核对版本和环境。`record/complete` 现有验收路径没有被放宽。
2. **范围用例与整份计划解耦。** 计划必须匹配任务 `testPlanId`，逐条核验 `directoryIds` 与 `selectedCaseIds` 内全部结果；忽略其他端的用例进度。范围内缺失、冲突执行结果、未知状态、失败/阻塞/未执行继续阻塞完成。记录阶段可以记录真实失败。保留执行 ID 和报告所属计划检查。
3. **发布不再检查他人岗位安装情况。** 只校验当前 Skill 和实际输入协议的兼容性。仓库维护时五包一起发布是分发策略，不是每个使用者必须安装五包的业务条件。

## 应继续保留的门禁

- 不唯一或冲突的项目/单据/正式关系；没有权限或明确授权的写入。
- 把他人的分支代码当成当前任务交付，或没有可信版本和范围映射却直接关闭任务。
- 测试通过缺乏真实证据、范围内用例未执行/失败/阻塞、当前测试版本不匹配。
- 活动阻断缺陷、没有复测记录的关闭、未经批准的暂不修复。
- 需求完成之前所有非取消开发任务到测试任务的唯一映射与范围聚合。
- 生产操作授权、实际发布范围、依赖闭包和合并后内容检查。

已有授权可供同一范围的 preflight/apply 使用；脚本要求确认参数不等于必须再问一遍。证据不足只暂停依赖该证据的步骤，不能把“接收任务”“记录进展”“测试完成”“发布放行”混成同一套门禁。

## 验证边界

新增行为测试覆盖：无产品包/部署/迭代接收测试、并发需求状态变化零写入、其他端未测不阻塞本端、本范围缺失/冲突/失败/未知状态继续阻塞、记录真实失败不冒充完成。全仓单元测试、协议副本、索引、安装页及 Codex 包一致性检查见本版发布记录。

本轮没有修改云效业务任务、执行测试用例、启动流水线或改变生产状态。回归测试使用模拟的云效读回，不能当作线上业务验收通过。
