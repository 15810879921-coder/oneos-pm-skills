# 交付描述 · 规则对照章节（修改前 / 修改后）

供 **YunxiaoPM 生成/回填【交付】描述**时调用本 Skill。输出**单独一章**，写入【交付】任务描述；**不**替代需求侧 `## 原始诉求（AutoRDO）` 全文结构（需求仍用常规清洗稿）。

## 何时强制

| 时机 | 动作 |
|---|---|
| 无单快轨 **创建【交付】**（有可写正文） | **必须**先 `$AutoRDO` 生成本章，再写入【交付】描述 |
| 标准路径 **设计完成** 回填【交付】（替换占位） | **必须**含本章；可与原型链接等同屏，但规则对照须独立成章 |
| 【交付】仍为占位 `等待设计任务完成后自动填入` | 不写本章 |

## 输入

- 需求当前「原始诉求（AutoRDO）」正文、标题、类型
- 或同等碎片材料（口令/台账行）
- **修改前 / 原始需求口径（强制优先）**：若存在桌面 **ONE-OS** 目录下该模块的**最初始版本**材料（如 `~/Desktop/ONE-OS/work/CURSOR/*车辆管理*.jsx` 内嵌 `requirementText`、初版 Axure/HTML 原型说明），**【交付】描述中的「修改前规则」与「原始需求」必须基于该初版**提炼，禁止用「无 V2 能力」一类空泛句代替初版实况

## 输出骨架（强制 · 单独成章）

当可定位到初版材料时，【交付】描述推荐结构：

```markdown
## 原始需求（初版·ONE-OS）
（据桌面 ONE-OS 目录该模块初版材料精炼；保留筛选/列表/操作等关键口径；无结尾句号）

## 规则对照（AutoRDO）

### 修改前规则
- …（与上节初版一致，关键短句）

### 修改后规则
- …（本期目标 / 当前原型 PRD 口径）
```

若无初版材料可溯源：仍输出规则对照两节，修改前标「待确认：初版材料路径」，并进 Plan。

### 写法

| 节 | 要求 |
|---|---|
| **修改前规则** | 改之前怎么算、怎么拦、怎么展示；**简单关键**（通常 1～5 条）；无结尾句号 |
| **修改后规则** | 改之后目标口径；**简单关键**；只写材料已明确的变化；不确定标待确认；无结尾句号 |
| **【新增】** | 修改前可写「无此能力 / 无此字段 / 无此校验」等一句；修改后写本期要具备的规则要点 |
| **【优化】** | 前后对照必须成对可读；禁止只写改后不写改前 |

### 禁止

- 把 AutoPRD 六大块、流程图、长验收清单塞进本章
- 臆造未在材料中出现的改后规则
- 与需求「原始诉求」互相覆盖（本章挂在【交付】；需求段保持原清洗结构）

## 与【开发】描述分工

| 工作项 | 规则写法 |
|---|---|
| 【交付】 | 调用 AutoRDO → **修改前 + 修改后**（本文） |
| 【开发】·【优化】 | 仅精炼 **修改前**（见 YunxiaoPM `dev-task-description.md`） |
| 【开发】·【新增】 | 不适用改前模板 |

## 待确认

改前/改后任一侧材料不足 → 该侧列 `待确认`，并按 [confirm-pending.md](confirm-pending.md) 进 Plan；未确认不得当定稿写入【交付】。
