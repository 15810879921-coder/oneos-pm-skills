# 10.2.10：恢复完成开发的产品交接死门禁

按用户明确裁决，回退 10.2.8 中“产品交接记录缺失只提示待补、不阻断完成开发”的行为。产品交接是完成开发的硬前提。

- 强制有效 `evidence.handoffEvidence`、产品 manifest、必读资料内容哈希、开发理解回执、当前范围与可信交付版本一致。
- 预检、执行前、每个阶段写入前都重新核验云效事实与材料；交接缺失、损坏、变化、不匹配或无法读取时，阻止完成开发及本流程测试任务创建/更新。
- 自动判断收到 `formal_handoff` 缺口时直接 `incomplete / stop_after_submit`；不弹确认把缺口变成放行，也不降为警告。
- 恢复完成时写入并完整回读开发理解回执，保留人工正文。保留 10.2.8 后补强的真实项目、父交付和需求关联校验。
- 可选工时失败仍可跳过，但该阶段的产品交接校验失败必须停止；旧预检和已完成回执不能豁免当前校验。

10.2.9 的 QA 范围计数、接收测试任务和岗位安装隔离修复保持不变。真实代码/版本、开发验证、测试任务完成与生产授权要求保留。该变更不回退云效单据，不执行业务测试或生产发布。

219 项 Python 单元测试通过，覆盖有效交接成功、无包预检及旧预检零写入、错误项目/父交付/需求关系、实时产品 manifest 缺失、资料变化、错误任务回执、可选工时阶段交接失败不得继续、自动完成缺口硬停止。交棒协议副本、索引、更新器、语义路由、安装页复制及五个 Codex 包逐文件一致性检查通过。测试使用模拟云效读回，不冒充线上业务验收。

按岗位更新所需 Skill 后新开会话，读取实际安装版本为 10.2.10；仓库五包一起发布不表示每位成员必须安装五包。Cursor 历史产物不变。
