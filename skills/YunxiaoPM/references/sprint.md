# 创建迭代并关联交付

产品经理可将已交棒（或已有编号）的多条【交付】任务打进云效迭代。迭代按端分列：Web 与小程序各有独立迭代，禁止混挂。

## 口令

```text
创建迭代：交付端=Web；版本类型=副；交付任务=ONEOS-a,ONEOS-b,ONEOS-c；名称前缀=统一运营管理平台Web端
创建迭代：交付端=小程序；版本类型=子；交付任务=ONEOS-99；名称前缀=统一运营管理平台小程序
创建迭代：交付端=共用服务；版本类型=副；交付任务=ONEOS-w1,ONEOS-m1,ONEOS-w2,ONEOS-m2
```

| 参数 | 规则 |
|---|---|
| 交付端 | **必选**：`Web` / `小程序` / `共用服务`；未给则停下询问，禁止默认猜。口令 `PC` 视为 `Web` |
| 交付任务 | **1..N 个任务编号**（逗号分隔）；禁止用标题凑数 |
| 版本类型 | 主 / 副 / 子；未点选则停下询问，禁止默认猜 |
| 名称前缀 | 单端可选；缺省 Web=`统一运营管理平台Web端`、小程序=`统一运营管理平台小程序`。最终名=`{前缀}{版本号}`。`共用服务`可不给前缀（两端各用缺省前缀）；若给则须成对写清，禁止一端共用另一端前缀 |

## 交付端 → 迭代条数（产品确认）

| 口令 `交付端` | 本步创建/复用迭代 | 挂接规则 |
|---|---|---|
| `Web` | **1** 个 Web 迭代 | 只挂带端侧标签 `Web` 的【交付】 |
| `小程序` | **1** 个小程序迭代 | 只挂带端侧标签 `小程序` 的【交付】 |
| `共用服务` | **默认 2 个**：Web 迭代 + 小程序迭代 | 按交付端侧标签自动拆分：`Web` 交付只进 Web 迭代，`小程序` 交付只进小程序迭代 |

`共用服务` 要点：

1. **默认一次建两端迭代**，同一口令、同一 `版本类型`、同一套起止日期（未给日期则询问或用项目默认，两端一致）。
2. 交付清单可混写 Web/小程序【交付】编号；执行前按端侧标签（或标题 `【交付】【Web】` / `【交付】【小程序】`）拆成两袋，分别挂到对应迭代。
3. 某一端袋为空 → 该端仍创建/复用迭代并回报「本端无交付可挂」，不得把对端交付塞进空端。
4. 禁止把两条端侧交付挂进同一迭代；禁止只建一端却回报「共用服务迭代已完成」。
5. 两端版本号各自按本端名称前缀取基线再递增，**禁止 Web/小程序串用同一版本序列**。

## 版本号 `V{主}.{副}.{子}`

| 版本类型 | 含义 | 递增 |
|---|---|---|
| **主** | 功能重制 | 主+1，副→0，子→0（V1.3.2→V2.0.0） |
| **副** | 新功能上线 | 副+1，子→0（V1.3.2→V1.4.0） |
| **子** | bug/优化 | 子+1（V1.3.2→V1.3.3） |

### 取基线再递增

1. 拉取当前项目云效迭代列表。
2. 从迭代**名称**解析 `V数字.数字.数字`；旧名 `V数字.数字` 视为 `.0`。
3. **按名称前缀分别**取最大版本为基线（主→副→子比较）；Web 前缀与小程序前缀互不串号。
4. 按用户点选类型递增，写入新迭代名称；`共用服务` 对两端各算一次。
5. 该前缀下无一可解析版本：基线 `V0.0.0` 再递增（主→V1.0.0，副→V0.1.0，子→V0.0.1）；或口令显式给起始版本（共用服务须分别给出或声明两端同规则自增）。

禁止：手填与规则冲突的版本号却声称自动生成；禁止用交付标题推断版本类型。

## 创建与关联

### 单端（`Web` / `小程序`）

| 步骤 | 动作 |
|---|---|
| 1 | 校验交付清单全部属于本端标签；混端则停 |
| 2 | 算出新版本 → 拼迭代全名 |
| 3 | 创建迭代（起止日期口令未给则询问或用项目默认，禁止瞎填） |
| 4 | **只挂【交付】**：本端 N 个交付任务挂迭代；交付失败不得报完成 |
| 5 | 幂等：同名迭代已存在 → 不新建，补挂尚未关联的交付，回报「复用迭代」 |
| 6 | 回报：迭代名、版本号、identifier、已关联交付编号、失败编号 |

### 双端（`共用服务` · 默认两迭代）

| 步骤 | 动作 |
|---|---|
| 1 | 拆分交付清单 → `Web袋` / `小程序袋`；无法判定端别的交付编号列出并停止 |
| 2 | 分别按本端前缀取基线、按同一 `版本类型` 递增，得到两个迭代全名 |
| 3 | 依次创建/复用 **Web 迭代** 与 **小程序迭代**（同一 Plan、同一确认；起止日期两端一致） |
| 4 | Web 袋只挂 Web 迭代；小程序袋只挂小程序迭代 |
| 5 | 任一端创建或挂接失败 → 回报两端真实结果，不得谎称双端都成功 |
| 6 | 回报须含两端：迭代名、版本号、identifier、已关联交付、空袋说明、失败编号 |

**禁止**把需求挂进迭代（需求侧「迭代」字段保持空）。不挂【分析】/【设计】除非口令显式点名。  
**不**在本步创建【开发】/【测试】。仍须 Plan 门禁。

### 挂接 API（已通 · 校验走 `/extra`）

```http
PATCH /projex/api/workitem/workitem/{交付id}?_input_charset=utf-8
{"workitemIdentifier":"{交付id}","propertyKey":"sprint","propertyValue":"{sprintId}","operateType":"COVER"}
```

校验（详情主接口**不**含 sprint，勿用其判空）：

```http
GET /projex/api/workitem/workitem/{id}/extra?_input_charset=utf-8
→ result.sprint[].identifier
```

清空误挂的需求迭代：同上 PATCH，`propertyValue:""` + `operateType:"COVER"`（或 `CLEAR`）。
