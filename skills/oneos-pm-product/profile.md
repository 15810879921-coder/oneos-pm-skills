## 做事偏好（别人该知道的）

1. **先对齐再铺开**：目标用户、范围、内容来源、验收不清时先收敛；设计基底已锁 OneOS V2，不折腾换肤比选。  
2. **早给可看的东西**：方案用短摘要 / ASCII / Mermaid；原型按生产级界面做，默认不是线框。  
3. **讲人话**：面向业务与领导能听懂；验收要写到「打开哪、点哪」。  
4. **闭环思维**：业务单据与财务实收实付要关联；反对「无关联却假性结清」的断头流（业财基准见法眼如炬 / KB）。  
5. **闭环五件套（新习惯）**：聊需求/优化时主动确认闭环、缺口、优化、可行性，并给更好办法——不等别人催。  
6. **租赁主链定版**：当前权威复审 **v2.5.8f**（客户创建→还车可闭环；缺口见 e2e §5）。  
7. **突击交付**：对分身默认「直接落需求 + 改交互」，做完再验收；云效默认先问再动。  
8. **省上下文**：短会话、窄检索、少开并行 Agent；长聊该收口就收口。  
9. **作战室联动**：修漏洞/补门禁/改原型后同步驾驶舱；**分析出的缺口/优化建议也要写入** `defects`（v1.4.18），并同轮 `npm run publish:war-room` 上对象存储。

## 审美与交互偏好（对外可说的摘要）

- **做页面禁止 AI 偷懒自造**：必须沿用已定版 OneOS V2 / 母版，先读规范再对照抄结构。  
- 台账：KPI + Pill Tabs +「更多筛选」收起式 + 表筛连体，不堆首屏大标题卡。  
- 详情/表单：扁平页头（返回 + 单号紫胶囊 + 清晰页名），不要白底描边整条顶栏卡片。  
- 一模块一侧栏入口，列表/详情同页切换。  
- 控件与状态走 OneOS V2 组件库；车牌无间隔点（如 `浙A88888F`）。  

细节清单见 [`habits.md`](habits.md) §3（含 §3.0 硬门禁）。
