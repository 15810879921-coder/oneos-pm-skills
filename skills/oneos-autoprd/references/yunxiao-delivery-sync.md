# 【交付】任务描述回填（设计完成 · 按编号）

与 **`$YunxiaoPM`** 组合。创建【交付】时描述保持占位 `等待设计任务完成后自动填入`；**本文件在设计完成（或显式同步）时**回填【交付】。

**禁止**按任务标题查找交付；勿加载已下架 lifecycle。

## 触发时机

| 时机 | 动作 |
|---|---|
| YunxiaoPM **设计完成**且材料就绪 | 必须回填【交付】描述 |
| 口令 `同步交付说明：交付任务=ONEOS-xx`（或需求编号可反查交付） | 按编号回填 |
| 仅创建【交付】 / 分析中 / 设计中尚未设计完成 | **不**写 PRD 正文（保持占位） |

## 前置

1. 已有【交付】任务编号：口令显式 > 需求 `## 工作项编号（系统）` > ASSOCIATED 反查校验。  
2. 冲突或缺少编号 → 停下询问；禁止按 `【交付】`+标题猜。  
3. **必须**已调用 **`$AutoRDO`** 产出规则对照章（见 AutoRDO `delivery-rules-chapter.md`）。  
4. 若本轮含原型：本地已有 `requirements-prd.md`（或本轮刚生成）。

## 写入内容（强制结构）

【交付】描述**必须**含独立一章（由 AutoRDO 写入）：

```markdown
## 规则对照（AutoRDO）

### 修改前规则
- …

### 修改后规则
- …
```

可选并列：

- 原型对象存储链接 + 产品说明摘要（来自 `$oneos-autoprd`）  
- 一句：`原始诉求见需求描述「原始诉求（AutoRDO）」`  

**禁止**仅用 `requirements-prd.md` 全文替换占位而省略规则对照章。  
不要删除或改写需求侧 AutoRDO 段（本步骤只改**任务**描述）。

## 执行顺序（设计完成组合）

```text
1. $AutoRDO → 规则对照章（修改前/后）定稿
2. AutoPRD 落盘 MD + 标注同步（若有原型）
3. 更新需求「产品说明（AutoPRD）」（若有）
4. 按交付任务编号 PATCH 任务描述：规则对照章为正文核心；可附产品说明/链接
5. 附件（ZIP/截图）由 YunxiaoPM make-export 流程负责；本文件不替代附件
6. 任一步失败 → 不得声称交付说明已更新 / 设计完成材料齐全
```

## 回报

- 交付任务编号、是否已替换占位、是否含规则对照章、MD 路径  
- 失败时列出缺项（无编号 / 无 AutoRDO 规则章 / 无 MD / 写入失败）

## 负向

- 创建交付当下灌入未完成的 PRD  
- 省略「规则对照（AutoRDO）」修改前/后两节  
- 按标题 list 复用「像交付的任务」  
- 引导旧 lifecycle 建同名任务
