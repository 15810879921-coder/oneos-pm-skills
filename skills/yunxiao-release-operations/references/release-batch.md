# 发布批次与A/B/C/D范围

## 入口

```text
/skill yunxiao-release-operations
组建发布批次：迭代=<精确名称>；需求=<REQ-ID,REQ-ID,...>
```

`需求`必须是用户明确选入本批的精确编号集合。项目从迭代反查，不接受手工项目覆盖。需求为空、重复、跨项目、跨迭代或无法唯一读取时零写入。

## 分类

先冻结迭代需求快照与选入集合，再运行：

```powershell
skill-run classify_release_scope.py --input scope.json
```

分类含义：

- A：本批选入，正式属于该项目/迭代，需求=`测试完成`、【测试】=`已完成`，`oneos.test-deployment/v1`和`oneos.qa-evidence/v1`均可解析且其中迭代ID等于本批迭代，QA用例计数闭合并零失败/零阻塞/零未执行、无活动缺陷、每条已关闭Bug有独立复测证据、暂不修复均有批准证据。进入发布范围。
- B：属于迭代但本批未选入，或已正式延期/移出且有原因。记录为延期范围，不阻塞本批。
- C：本批选入但test部署、测试证据清单、用例或缺陷门禁未完成。阻塞本批。
- D：跨项目/跨迭代、QA证据迭代与命令迭代不一致、正式关系缺失、同一需求同时选入和延期、编号不存在或范围冲突。阻塞本批。

分类输入不得再使用`qaEvidenceComplete=true`代替证据。每条需求必须携带并由脚本逐字段校验：

- `testTaskId`及完整`testDeployment`对象，schema=`oneos.test-deployment/v1`；
- 完整`qaEvidence`对象，schema=`oneos.qa-evidence/v1`、`sourceVerified=true`，并包含证据清单SHA-256；
- 发布时实时读取的完整`bugs`数组；无Bug时为空数组，有Bug时只能是带独立`oneos.bug-retest/v1`的`已关闭`，或带批准证据的`暂不修复`；该数组必须与QA证据中的`bugSnapshot`及其SHA-256一致。

项目、迭代、需求、测试任务、部署执行或部署版本任一不一致，均归C类并禁止进入发布范围。

只有`A非空 && C为空 && D为空`时才允许写云效。

## 创建【执行】任务

通过后：

1. 在迭代内按`项目ID + 迭代ID + 排序后的A类需求ID + release_batch`生成幂等键。
2. 创建或复用唯一顶层`【执行】<迭代>-<批次摘要>`任务；不得把【执行】挂在【交付】下。
3. 正式关联A类需求，以及这些需求各自的【交付】和已完成【测试】任务。
4. 在描述中写入受管范围区块：A/B/C/D快照、QA证据摘要、生成时间和幂等键；保留人工内容。
5. 回读项目、迭代、全部关系和受管区块。B类仅记录，不建立本批发布关系。
6. 返回`执行任务ID`，下一条固定为：

```text
/skill yunxiao-release-operations
准备发布：执行任务ID=<执行任务ID> 迭代=<精确名称>
```

重复命令必须复用同一任务；存在多条相同幂等键任务时阻塞，不自动选最新。
