# 分配任务的技术实施方案

分配任务不再向开发任务描述写下一步执行口令。先通过`yunxiao_cli_allocate_task.py analyze`读取`ASSOCIATED→需求`的完整说明，再由执行Agent基于该说明生成方案文件，并在预检后写入开发任务的受管`## 技术实施方案`区块。

## 必填结构

```markdown
# 技术实施方案：<需求编号> <需求标题>

## 实现范围
- 受影响的前端、后端、数据、配置和权限范围；无法由需求确认的部分明确写“待代码侧核实”。

## 处理逻辑
- 正常流程、异常流程、边界条件和兼容策略。

## 实施步骤
1. 可按顺序执行的实现动作；未核实的文件或接口不得编造。

## 验证标准
- 开发侧自动化验证、页面/接口验证、边界和回归检查。
```

## 约束

- 必须包含关联需求编号、实现范围、处理逻辑、实施步骤、验证标准。
- 不得包含`/skill`或`/go`命令，不得把待执行动作伪装为已完成。
- 未经代码侧核实不得指定具体文件路径、接口字段、表名或配置键；需要核实时明确列为后续开发动作。
- 预检冻结需求描述和方案哈希；任一变化后必须重新分析并预检。
- 开发任务描述只替换本Skill托管区块，区块外人工内容保持不变。
