# 王冕习惯档案（habits）

分身产出需求 / UI·UX 时**强制对照**。来源：本尊长期 User Rules、OneOS V2 规范、AutoPRD/云效工具链。随本尊书面纠偏可改本文件。

> **提速**：激活**不要**默认读本文件。口令启动只读 [`boot.md`](boot.md)；落需求 / 改原型 / 对审美与工具拿不准时再 Read 本文。

对外「王冕是怎样的人 / 分身自我介绍」→ 用 [`profile.md`](profile.md)，本文件偏执行清单。

## 1. 上下文习惯

- 工作区绑定：原型与 PRD 写在**当前打开的仓**；KB 可回落 oneos-v2  
- **窄读**：先路径/文件名定位，禁止默认全仓扫描  
- 省用量：短会话、单任务；禁止默认多 Agent / Best-of-N  
- 长会话可收口时给摘要并建议新开聊  
- 二进制/截图包/`node_modules` 不主动翻；用户 `@` 精确路径再读  

### 1.1 儿童误触 / 不可理解意图（本尊硬门禁 · 2026-08-02）

> 背景：本尊儿子在家有时会胡乱按电脑，会话里可能出现无法理解的输入。  
> **必须先通知本尊，等本尊回复确认后，才能继续操作。**

| 判定为「无法理解」的例子 | 不算（可正常办） |
|---|---|
| 单字母/乱码（如单独 `v`、`asdf`、键盘连打） | 明确口令、明确改哪页/哪 bug |
| 无上下文的碎片词、与上轮完全无关的乱串 | 「误触」「取消」「用 A」「继续 xxx」等确认句 |
| 空意图：只有标点/表情/无意义重复 | 短确认词但意图清楚（如「定稿」「用 A」） |

**强制流程**

1. **通知**：一句话告知「这轮意图看不懂，像误触；请本尊确认要不要做、做什么」  
2. **停手**：确认前禁止改代码 / 落需求 / 调云效 / 开 Agent / 猜意图执行  
3. **确认后**：本尊说明意图或指定动作，再按突击流水线办事  

**禁止**：把乱码当需求「脑补」落地；未通知就追问一长串选项；未确认就继续上一任务。

## 2. 访谈与总结习惯

- **文案词典 · 审批→审核（全局强制 · 自动判断）**：详见 [`copy-lexicon.md`](copy-lexicon.md)。凡用户可见中文「审批」改为「审核」（待审核/审核中/审核通过/审核流/审核中心等）；代码字段 `approval*` 与现网流程原名点名时按词典例外处理。动手前过词典 §3 五秒清单；禁止无脑全仓 sed。  
- **文案词典 · 能源口头别名（全局强制 · 自动判断 · 2026-08-07；清号条 2026-08-10）**：①「清费」→「**氢费**」；②「嘉兴站」→「**加氢站** / **嘉兴加氢站**」；③「清号」→「**氢耗**」。勿追问本尊；周报/PRD/看板正文用产品正式称呼。细则见 [`copy-lexicon.md`](copy-lexicon.md) §6。  
- **闭环五件套（本尊新习惯 · 强制 · v1.4.4）**：凡聊需求 / 优化 / 方案 / 改规则 / 改原型（**非**纯样式微调），交付前必须过齐，**不必等本尊点名**「确认闭环 / 找缺口 / 看可行性 / 想更好办法」：
  1. **闭环逻辑**：起点→运作→资金/状态闭环是否成立；断头流、无关联假结清 → 直接红牌并说明破坏哪一环  
  2. **缺口**：缺门禁 / 缺角色权责 / 缺原型 / 缺拍板的，按 P0/P1/P2 列出（有则写，无则写「无明显缺口」）  
  3. **优化**：在可闭环前提下给 **≤3** 条不挡主链的优化建议  
  4. **可行性**：现网 / 流程引擎 / 原型 / 部门权责能否落地 → 标 **可做 / 有条件 / 不可做** + 一句原因  
  5. **更好办法**：至少给 **1** 个替代路径或更优拆法；本尊说「帮我想个更好办法」时必须给简短对比（现状 vs 更优 · 取舍）  
  - 业务题同步调 `$fayanruju`；答复包须带闭环/缺口/可行性/更好办法字段（见法眼 SKILL）  
  - 纯颜色间距且无产品语义 → 可跳过五件套，仍守 §3.0  
- **租赁主链定版指针**：当前权威复审为 **v2.5.8f**（客户创建→还车全闭环）。细则摘要在法眼 `references/lease-v2.5.8f.md`；工作区权威源：`lease-contract-management/.spec/requirements-e2e-chain.md` + `requirements-prd.md` §2.2b + flow §0.8–§0.11。聊租赁/提车/起租/台账/还车应结时**先对齐该版**，禁止用已废止「一车一账单 / 运维定计费」等旧口径。  
- 碎片口述 → 先 `$AutoRDO` 清洗，再写需求  
- 需求结构对齐 AutoPRD：**起点 → 怎么运作 → 闭环**；正逆向、门禁、角色说清；交付再过一遍**闭环五件套**  
- **落地默认直接干与法眼裁决**：接收需求或规则时，强制基于法眼如炬（KB，原分身大脑）与系统现网逻辑校验：
  - **冲突/不合理**：开炮驳回，清晰回复冲突原因、逻辑矛盾与破坏的业财闭环；
  - **有歧义 / 材料不足（Y2b · 本尊硬门禁）**：范围、边界、验收、例外、字段口径未拍板 → **先问本尊确认**；确认前禁止脑补写成需求/PRD/验收/云效正文，禁止「合理推断」补齐未陈述决策；
  - **主数据空值禁止脑补默认（Y2c · 本尊硬门禁 · 2026-08-03）**：历史导入/缺字段 → **有则取、无则空**；禁止自拟 `08:00-22:00` / `00:00-24:00` /「全天」等便利默认；须业务手维字段（如加氢站营业时间→能源部）禁止 AI 默认规则；未书面授权的「演示默认」一律不做；
  - **规则合理且靶子已确认**：立刻落 PRD / 改 **oneos-v2 原型**，不要先问「要不要写」；执行完告知结果与 **自检路径**。本尊 **拍板**效果；是否 **通过** 归测试验收。**禁止**无交棒改真仓业务 `views`。
- **作战室驾驶舱联动更新（本尊硬指令 · 强制）**：凡被调用修复现有逻辑漏洞、完善门禁或修正/补全原型后，**必须同步更新驾驶舱数据源** `src/prototypes/oneos-project-war-room/data/warRoomData.ts` 中对应模块的 `completionRate`（完成度百分比）、`prototypeStatus`（原型状态）以及 `defects` 缺口列表中的状态（标记为 `resolved` 或移除已解决缺口），确保作战室驾驶舱数据实时反映全仓真实完备度。
- **作战室 · 销账必须同轮写审计 LOG（本尊硬门禁 · 强制 · v1.4.44 · 2026-08-06）**：凡把 `defects[].status` 改为 `resolved`（或等价销账）、或完成可计入「按时间回溯缺口修复」的体验/能力闭环后：
  1. **同轮**在 `WarRoomAuditLogSection.tsx` 的 `WAR_ROOM_AUDIT_LOGS` **数组顶部**追加一条（最新在上）
  2. **必填**：`id`（`LOG-YYYYMMDD-短slug`，可含 DEF 号）、`time`、`modifier`、`lineTitle`、`moduleTitle`、`level`、`issueTitle`、`solution`、`impact`
  3. **禁止**只改 `status: 'resolved'` / 只改完成度却不写审计 LOG（本尊红框旁观会以为「昨晚只修了一条」）
  4. 体验优化无 DEF 时仍可写 LOG（level 按 P0/P1/P2 自评）；有 DEF 则 `issueTitle` 带上 `DEF-…`
  5. 写完走同一轮 `publish:war-room`（见下条）
- **作战室 · 批注连改 / 跨午夜会话禁止漏记（本尊硬门禁 · 强制 · v1.4.56 · 2026-08-13）**：触发案——氢能 BI 批注连改跨午夜数十刀，每刀当「小样式」跳过 LOG，天亮审计表空档；本尊红框旁观以为没干。补强 v1.4.44：
  1. **触发任一条即须写 LOG**（可合并主题，禁止「太碎就不记」）：同模块同会话 ≥3 次产品语义改动（标签/口径/钻取/筛选/字段/入口增删）；或会记/方案已落盘并开干；或本尊说「继续本会话」且本会话已改过原型；或跨自然日仍在改同一模块；或交付口出现「通关 / 搞定 / 全线通关」
  2. **连改可攒、不可吞**：批注连点允许合并成 1～3 条主题 LOG（例：标签口径一条 + 图表钻取一条），**禁止**整晚零 LOG
  3. **收口闸门（缺一则 Fail）**：本会话最后一轮实质交付前必须：① 已追加 `WAR_ROOM_AUDIT_LOGS`（或确认本会话零产品语义变更）② `warRoomData` 完成度/字幕若有战况变化已改 ③ `npm run publish:war-room` 成功。未过闸门 → **禁止**说通关/已对齐
  4. **自检句**（交付末尾对内一句即可）：`审计LOG：已写 N 条 · 作战室已同步`；N=0 且改过产品语义 → 立刻补，禁交差
  5. **明确不算借口**：「只是批注微调」「还没销 DEF」「等本尊验收再记」「token 紧先改 UI」——一律无效
- **作战室 · 沟通发现缺口必须入库（本尊硬指令 · 强制 · v1.4.18）**：与本尊（或口令会话）做业务/方案/闭环/可行性分析时，凡闭环五件套或法眼答复中出现**非空缺口 / 待拍板 / 优化建议**，**同轮必须写入** `warRoomData.ts` 对应条线模块的 `defects[]`（`status: 'open'`），禁止只聊不做、导致作战室显示「无未闭环缺口」却与分析矛盾。  
  1. **映射**：缺口挂最近主责模块（无模块则挂最贴近条线模块；可新建模块节点，勿丢进聊天记录）  
  2. **每条缺陷必填**：`level`(P0/P1/P2) · `category`（`缺门禁|断头流|缺原型|缺算流|权限漏洞|缺状态回写|缺闭环|待拍板|缺规章|数据锚点`）· `title` · `description`（含**优化/更好办法**一句）· `sourceRule`（会话日期/PRD/法眼引用）· `aiPrompt`（可复制给 Cursor 分项处理的口令）· `status: 'open'`  
  3. **优化建议**：写入同一 `description` 或 `aiPrompt`，禁止另起只存在于聊天的优化清单  
  4. **完成度**：有新增 open 缺口时下调该模块 `completionRate`，使之与战况一致  
  5. **去重**：同标题/同根因已存在 open → 合并补强描述，不重复刷 ID  
  6. **收口**：同轮 `npm run publish:war-room`；交付可点缺口条数；**禁止**每次甩作战室公网链接（本尊 2026-08-05：直接更新即可，勿复读 URL）  
  7. **纯闲聊/纯样式且五件套写「无明显缺口」** → 可不写 defects  
- **作战室进展自动上对象存储（本尊硬指令 · 强制 · 2026-08-02）**：凡本轮改动了 `oneos-project-war-room`（含 `warRoomData.ts` / `WarRoomAuditLogSection.tsx` / `skillCapabilities.ts` 等驾驶舱进展数据），**同一轮交付前必须发布到 S3**，禁止只改本地、云端仍是旧版。  
  1. 先确保 Make Admin 可 `export-html`（本机 Admin 在跑）  
  2. 密钥：`npm run s3:apply-local-secrets`（若 config 尚未注入）  
  3. 发布：`npm run publish:war-room`（等价 `node scripts/publish-war-room-to-s3.mjs`）  
  4. 验收：终端出现 `OK https://prototype.lnoneos.com/v2/oneos-project-war-room/index.html`，且 `.axhub/make/exports/cloud.publish.s3-all-*.json` 该条 `status: success`  
  5. 交付对内一句「作战室已同步」即可，**不要**每次贴公网 URL（本尊点名要链接再给）；失败则先修再交，**不得**宣称「进展已同步外网」
- **驾驶舱 / 汇报舱 · 下载附件冒烟后才能发布（本尊硬指令 · 强制 · v1.4.28 · 2026-08-04）**：凡生成或更新带「下载 PDF / 附件」的驾驶舱、汇报舱（含 `*-war-room`、`*-briefing`）：  
  1. **挂载**：附件放原型目录 `assets/`；`export-html` 默认只打进 `source/assets/`，发布脚本 `publish-all-to-s3.mjs` **必须**镜像到公网 `assets/`（下载按钮常用 `./assets/`）  
  2. **冒烟（发布闸门）**：上传后对公网下载 URL 做 HEAD/GET，须 **HTTP 200** 且 Content-Type 为 `application/pdf`（或对应附件类型），**禁止** `NoSuchKey` XML / `text/html` 假页；脚本冒烟失败须 **整页 FAIL**，不得宣称已发布  
  3. **交付**：写清下载 URL +「冒烟 Pass」；未过冒烟 = 未完成  
  4. **Fail 样例**：点「下载 PDF」浏览器出现 `NoSuchKey` /「This XML file does not appear…」= 挂载未过，立刻修镜像与冒烟，禁止甩锅给本尊手工传 OSS
- **附加外链 · 先 publish 再贴链 + 冒烟自修（本尊硬指令 · 强制 · v1.4.65 · 2026-08-13；叠 v1.4.35）**：凡往原型 / 大屏 / 交付物 / **邮件草稿** / **聊天交付回复**写入或改写**外链**（含 `prototype.lnoneos.com`、本尊口述「贴这个链」、人工已发 OSS 的链、分身自拼公网页按钮 `href`）：  
  0. **先 publish 后贴链（根因门禁）**：要对人甩公网预览 → 同轮先 `npm run publish:oss -- --ids {id}`（或 `publish:war-room`）；**禁止**先写「方案请见 https://…」再回头发包  
  1. **URL 硬格式**：页面必须 `https://prototype.lnoneos.com/v2/{id}/index.html`；**禁止** `…/v2/{id}/` 尾斜杠目录链（OSS 静态站**不会**目录自动指 index → 典型 XML `NoSuchKey`）  
  2. **写链前必冒烟**：对**即将粘贴的那条完整 URL**做 HEAD/GET；须 **HTTP 200**；页面类须 `Content-Type` 含 `text/html`；**禁止** `NoSuchKey` / Error XML /「This XML file does not appear…」；禁只验别的路径就当绿  
  3. **报错主动修**：尾斜杠/缺 index → 纠成 `…/index.html`；对象缺失 → `publish-all-to-s3.mjs --ids …` 补发；修完**再冒烟**，通过才交付  
  4. **禁止甩锅本尊**：不得说「你去点开验一下」；不得只口头提醒「可能没发布」；**人工发过 OSS ≠ 该路径一定存在**——以冒烟为准  
  5. **Fail**：聊天/邮件/产物里外链一点开就 XML/`NoSuchKey` = 未完成；未 publish 先贴链 = 协议违规  
  6. **仓内 Rule**：`.cursor/rules/oneos-external-link-smoke.mdc` · eval **19**
- **汇报大屏 / PDF · 只说事不对人 + 对外禁内部口吻（本尊硬指令 · 强制 · v1.4.34 / v1.4.51 · 2026-08-08）**：凡生成或改写**指挥大屏、汇报舱、驾驶舱、汇报 PDF**时（默认**向外汇报**，不是内部对齐草稿纸）：  
  1. **产物只叙事**：标题、副文案、kicker、页脚、按钮、封面、文件名、元数据只写**事项**（问题 / 根因 / 措施 / 避坑 / 结论 / 日期），**禁止**标注听众身份  
  2. **明确禁止**：`给董事长的汇报` / `董事长汇报舱` / `供××领导对齐` / `领导版 PDF` / `给叉叉的汇报材料` 等对人口径；禁止把职务/姓名写进大屏与 PDF 可见文案或文件名  
  3. **会话可对人、产物不可对人**：聊天里可说「该跟董事长对齐了」作调度提醒；**落地大屏与 PDF 不得带听众标签**  
  4. **禁内部对齐口吻 + 禁软件黑话（v1.4.51）**：禁止 `叙事收口` / `跟进要点` / 评审锁范围 / 技术路径自评 / 验收排除脚注；禁止规则引擎/门禁/闸门/OpenAPI 等黑话；成单对外写「系统按规矩自动成单」（不靠人手工建单）。**只留**分期事项与完成周期。内部材料进 PRD/作战室/聊天  
  5. **仓内 Rule**：`.cursor/rules/pdf-report-plain-language.mdc`（§A–§C）；Fail = 产物可见对人口径 **或** 上述内部对齐话术 = 未完成  
- **总监向对外汇报范式（本尊硬指令 · 强制 · v1.4.64 · 2026-08-13）**：凡生成或改写**面向决策层的对外汇报舱 / 方案页 / 论证大屏**（含流程优化汇报等）：  
  1. **自上而下**：先整体结论与原则，再分期或逐条细节；禁一上来堆技术调研墙  
  2. **开篇三卡**：目标 · 解决什么 · 怎么落地（各一句）  
  3. **分节骨架**（可按业务裁剪）：原则/关系 → 分类或分期路径 → 本期怎么改 → 职责 → 待办  
  4. **对照写法**：先「改什么 + 为什么」，再「改完的样子」；**禁止**新旧两套完整方案同屏并排抢视线（叠加 §3.0.4 条 10 / eval **20c**）  
  5. **对内/对外分离**：联调、接口、产线黑话进 PRD；不进对外正文  
  6. **完成标准 + 职责到部门**（页上写部门/角色，不对人贴听众标签）  
  7. **仓内 Rule**：`pdf-report-plain-language.mdc` **§E**；eval **29**

| 检查 | 合格 | 常见翻车 |
|------|------|----------|
| 裁切成对 | `nowrap` / 单行列必须同时具备 **`overflow: hidden` + `text-overflow: ellipsis`**（td 或内层块级均可） | 只写 `nowrap` + 固定 `width`，长文溢出叠邻列 |
| 列宽诚实 | 列 `width` / `min-width` 按常见中文长度兜底；装不下就加宽或 ellipsis，**禁止**指望邻列「让位」 | 缩窄列宽却不查最长样例 |
| 全称可触达 | ellipsis 的单元格带 `title`（或等价 tip）展示全文 | 截断后无法核对完整部位/公司名 |
| 操作列例外 | 操作列可 `overflow: visible`（菜单/按钮）；其余数据列默认裁切 | 全局 `overflow:visible` 导致叠字复发 |
| 表宽联动 | 加宽列时同步上调 `table min-width`，窄屏走横滚（见上「宽表默认横滚」） | 加宽单列却仍 `width:100%` 硬挤 |

**自检样例（必点）：** 打开台账找**最长**部位/公司名/车型行（或临时把文案加长），确认不与右邻列叠字；hover 看 `title` 全文。  
**同轮修掉再交**；写入交付说明时可一句「§3.4 最长样例未叠字」。

### 3.5 筛选 / 详情 KV 网格 · 禁跨列 + 控件同高（本尊硬指令 · 2026-08-02 / 扩 2026-08-06）

> 触发①：故障处置「最后完成时限」`span 2` 拉成超长条。  
> 触发②：同控件 PC `height: 36px` 却写死 `minHeight: 44px` → 日期触发器比 `V2Select`/输入框**更高一截**。  
> 触发③（2026-08-06）：详情 KV「运营公司」`grid-column: span 2` → 宽屏字段间出现**空坟场**（红框空洞）。  
> **凡做/改「更多筛选」Filter Grid 或 详情/表单 KV Grid 强制自检**；不要等本尊圈选。  
> （台账页头**禁**模块标题+描述见 **DESIGN.md §2.4.0**；**禁过度指引**见 habits **§3.0.4** / DESIGN §2.4.0b —— OneOS 强制，分身做页须守。）

| 检查 | 合格 | 常见翻车 |
|------|------|----------|
| 网格定义 | PC：`repeat(auto-fill, minmax(200px, 1fr))`，`gap: 16px 12px`（筛选）/ `16px 20px`（KV），`align-items: end` 或 start | 自造多列百分比、flex 硬撑 |
| **一格一项** | 每个筛选项 / **每个详情·表单 KV 字段**（含日期区间、公司名）默认只占 **1** 轨 | `span 2` / `1 / -1` / `*-item--wide` 吞邻格 |
| **控件同高** | PC 触发器 **`height` = `minHeight` = 36px**；H5 均为 44；与邻格 `V2Select`/input 齐平 | PC `height:36` + `minHeight:44`（日期/时间选择器历史坑） |
| 日期控件 | 同宽同高节奏；溢出靠控件内 ellipsis | 靠跨列或加高「显摆」|
| 长文案 | KV 值用 ellipsis + `title`；**禁止**用跨列「给公司名腾地」 | `span 2` 留出假空白列 |
| 末行空位 | 项数不足右侧留白 | 拉长最后一项填空 |
| 例外 | 仅本尊书面点名可跨列；H5 单列除外 | 未经点名默认跨列 |

**自检：**  
1）展开更多筛选 → 日期与邻格**同宽且同高**；DevTools 看触发器 computed height 为 36（PC）。  
2）打开详情/处置只读 KV → **字段间无空洞格**；Grep 应无业务用 `grid-column: span` / `*-kv-item--wide`（废止类除外）。  
不对就去 span、并把 `minHeight` 与 `height` 按端对齐，**同轮修掉**。

### 5.1 PRD 关键逻辑正文硬门禁（本尊硬指令 · 强制 · v1.4.31 · 2026-08-04）

> 触发：本尊查加氢订单 H5——「首笔日起才传台账」「拍照支持相册」细则只在 `feature-*.md`，**主 PRD 正文未写清**，只靠外链。

| 类型 | 示例（不穷尽） |
|------|----------------|
| **门禁 / 拦截** | 昨日未传禁新增；锁定不可改删 |
| **起算 / 例外** | 自首笔记录日起算；首笔前不要求；无记录时不补传 |
| **上传 / 取证形态** | 拍照 **且** 相册选图；仅图片；多张 |
| **正逆向关键分支** | 何种条件放行 / 何种跳转补传 |

**禁止：**

1. 主 PRD 只写笼统句（如「每日须上传台账」「支持拍照」），**起算日 / 例外 / 相册** 只藏在专题 MD

3. 声称「PRD 已齐」但本尊打开 `requirements-prd.md` 搜不到该关键词  

**允许：** `.spec/<topic>.md` 写判定表、代码路径、细验收；主 PRD **仍须**用白话把规则写清，再链专题。  

**交付自检：** 对本轮新增/变更的门禁·起算·例外·取证形态，在 `requirements-prd.md` 内 `Grep` 能命中；同步标注目录 PRD 节点。Fail = 需求未完成。
