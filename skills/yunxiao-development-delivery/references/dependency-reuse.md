# 本机依赖复用

## 适用范围

仅用于当前开发机器上的 `开始开发`、`开始修复bug`、一键开发和一键修复的本地工作区准备与验证。它不修改 Dockerfile、云效测试/生产流水线或远端缓存，也不得把本机依赖目录提供给 CI。

创建或复用分支只做发现和记录，不下载、安装、复制依赖，也不生成 `target`、`dist` 等构建产物。首次需要编译、测试或真实页面验证时，才按本规则使用已记录的策略。

## 先发现，再决定

对每个实际仓库分别计算依赖指纹并记录：

- 前端：包管理器、`package.json`、锁文件、工作区配置、`.npmrc`（如有）、Node 与 pnpm 的实际版本。
- Maven：`pom.xml`、父 POM/多模块 POM、Maven Wrapper 配置（如有）、JDK 与 Maven 的实际版本。

通过当前项目实际生效的命令或配置解析缓存目录：

- Maven 优先读取 `settings.localRepository`；不可读取时检查当前机器生效的 Maven settings。不得假定 `~/.m2/repository` 或任何固定盘符。
- pnpm 通过 `pnpm store path` 读取；不得假定 `/pnpm/store`、用户目录或 CI 路径。

解析失败时只写“缓存路径未解析”，选择增量安装回退；不得猜测目录、创建空目录或伪造缓存命中。

## 复用规则

| 工作区与条件 | 策略 |
|---|---|
| 同一物理项目目录；前端指纹和 Node/pnpm 版本均一致；现有依赖可读 | 直接复用当前目录的 `node_modules`，不执行安装。 |
| 独立 Git worktree；前端指纹和 Node/pnpm 版本均一致；pnpm store 可用 | 不共享或复制其他 worktree 的 `node_modules`；首次验证前使用当前机器实际 store 的离线、冻结锁文件安装，生成本 worktree 自己的链接。 |
| Maven 项目；实际本地仓库可读且依赖已命中 | 复用 Maven 本地仓库；不得复用其他分支的 `target`。 |
| 指纹、Node/JDK/包管理器版本不同，缓存缺失，或依赖校验失败 | 仅在首次真实本地验证前执行一次冻结锁文件/确定版本的增量安装，并写明触发原因。 |

前端安装必须保持锁文件冻结；Maven 必须保持项目既有 Wrapper、镜像和 profile 约束。不得为了复用而降级运行时、修改锁文件、切换包管理器或使用忽略依赖一致性的参数。

## 记录与失败处理

在首次 `【研发启动】` 评论和本地执行回执中补充：

```text
依赖指纹：<摘要>
运行时：<Node/pnpm 或 JDK/Maven 实际版本>
缓存目录：<动态解析结果；未解析时写未解析>
依赖策略：直接复用|本地仓库复用|pnpm store 离线复用|增量安装
网络下载：否|是
回退原因：<无|锁文件变化|运行时不一致|缓存缺失|校验失败>
```

依赖安装、构建或测试失败时，不得删除缓存、复制其他分支的依赖目录或反复重试。记录失败原因；只有依赖指纹、运行时或缓存状态发生变化后，才允许再次尝试。

构建产物始终属于当前分支/当前 worktree：`target`、`dist`、测试报告和临时生成物不得作为依赖复用材料。
