冲突/过期处理：新环境或组织网络策略不允许该代理时暂停受影响的网络步骤并说明差异；重新核验代理或取得明确调整后继续，不把历史连通性当作当前证据，不静默改变已授权目标分支。

## 无人值守阿里云认证

```text
ID：DB-C-006
状态：confirmed
适用范围：Windows 服务、计划任务、CI Agent 或其他无人值守进程通过阿里云 CLI/SDK 调用云资源 API 的开发与改造；仅约束认证材料选择、存储、装载和身份预检，不自动授权任何云资源写入或权限扩大。
规则或复盘：无人值守任务不得把交互式 OAuth 登录令牌、CLI profile 或其跨机器副本作为长期认证来源。运行在阿里云 ECS 且具备条件时优先使用实例 RAM 角色；非 ECS 环境确需长期 AccessKey 时，必须由何斐明确确认，使用专用 RAM 子账号和满足任务所需的最小权限，将 AccessKey 保存在运行身份可读取的操作系统安全凭据存储中。程序只在当前进程内读取凭据，并通过进程内存或子进程环境变量传递；禁止把 AccessKey ID、AccessKey Secret、令牌或完整认证配置写入代码、脚本参数、普通配置、日志、聊天、测试数据、构建产物或 Git 仓库。每个账号独立执行 `GetCallerIdentity` 并与预期账号严格比对，再做目标资源只读预检；身份或权限不符时只停止该账号，禁止回退到主账号密钥、管理员密钥或扩大权限兜底，整体结果必须如实标记部分失败。
证据来源：TODOS-7 阿里云白名单无人值守任务中，跨机器复制 OAuth 凭据出现到期后自动续期失败，且重新授权时发生 profile 与账号对应关系交换；随后本机 Windows 普通凭据中的两套 RAM 用户 AccessKey 均通过 STS 身份核验，其中一套通过目标 ECS/RDS 只读查询、另一套准确暴露目标安全组权限缺口。何斐于 2026-09-07 明确要求将该方式加入 development-brain 开发约束。
验证：开发大脑预检命中 DB-C-006 时，先确认运行环境是否支持工作负载身份，并检查代码、脚本、配置、日志、测试数据、构建产物和暂存差异不存在高置信度密钥或令牌；在目标运行身份下读取凭据，分别执行 STS 身份核验和目标资源只读查询。只有账号 ID、地域、目标资源和最小权限均符合本次明确授权，才允许进入后续动作；密钥值不得出现在验证回执。
记录日期：2026-09-07
复核触发：阿里云认证机制、实例 RAM 角色可用性、运行身份、操作系统凭据存储、账号映射、最小权限策略或组织密钥轮换制度发生变化。
冲突/过期处理：目标仓、组织安全制度或运行平台存在更严格的无密钥认证要求时以其为准；禁止长期 AccessKey 时不得以本规则绕过。凭据泄露、账号不符、权限漂移或身份读回失败时立即停止受影响账号，禁用或轮换由授权人员处理，不在代码侧扩大权限或降级安全门禁。
```
