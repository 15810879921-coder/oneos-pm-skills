# 生产后产品验收

## 口令

```text
$YunxiaoPM
拉取待验收需求：发版任务=TASK-900

$YunxiaoPM
验收通过：发版任务=TASK-900；验收人=王经理；证据=ACCEPTANCE-ID或URL

$YunxiaoPM
验收不通过：发版任务=TASK-900；验收人=王经理；原因=...；证据=ID或URL
```

`发版任务`是唯一锚点；不接受单个需求编号替代，不按标题猜范围。

## 通过门禁

1. 发版任务唯一且状态=`发布完成`。
2. 本批需求全部=`发布完成`（验收通过时亦允许已完成/已关闭续跑）；范围可由 **发版→需求** 或 **发版→【交付】→需求** 解析，不要求发版任务描述含 `oneos.release-production/v1` 生产证据区块。
3. 每个需求对应唯一源`【交付】`，交付保持=`处理中`（通过续跑允许已完成）。
4. 发版任务关联的无交付已完成Bug全部与发版迭代一致、已处于`已完成|已关闭`、具有独立复测证据，且只回读验收证据、不再次流转状态。
5. 验收人、证据非空，证据对应本批验收范围。
6. 先dry-run并经YunxiaoPM Plan确认。

执行入口：

```powershell
skill-run accept_release.py pass `
  --release-id <云效内部ID> `
  --release-sn TASK-900 `
  --acceptor '王经理' `
  --evidence 'ACCEPTANCE-ID-or-URL' `
  --dry-run
```

去掉`--dry-run`后，脚本先向发版任务、每条需求、每个源【交付】和本批无交付已完成Bug写入同一`oneos.product-acceptance/v1`验收区块并回读，再依次推进本批需求`发布完成→已完成`、对应源`【交付】处理中→已完成`、发版任务`发布完成→已完成`。无交付已完成Bug只写证据并回读，不改变其已完成状态。每个对象均按真实下一状态动态解析，不使用本地硬编码ID。

## 验收不通过

```powershell
skill-run accept_release.py fail `
  --release-id <云效内部ID> `
  --release-sn TASK-900 `
  --acceptor '王经理' `
  --evidence 'ACCEPTANCE-ID-or-URL' `
  --reason '验收失败原因' `
  --dry-run
```

确认后向发版任务、需求、源交付和本批无交付已完成Bug写入并回读统一“不通过”证据；尝试把发版任务从`发布完成`转到项目真实`发布失败`，若流程不支持则保留实际状态并在证据中标记`notSupported`。需求与源交付保持真实状态，无交付已完成Bug不回退，不得伪装为生产流水线失败，也不得擅自回退需求。

无论状态迁移是否受项目流程支持，下一步都固定输出：

```text
$YunxiaoQA
接收发布回流：发版任务=TASK-900；触发=产品验收失败；证据=ID或URL
```

后续必须经过正式缺陷、开发修复、test部署、逐Bug复测和回归证据，再由发布Skill执行`重新发布`；不得直接再次验收或直接重跑生产。

## 幂等与部分失败

- 幂等键=`发版任务内部ID + 验收结论 + 验收证据`。
- 重试只替换同一受管验收区块，保留人工描述。
- 首次执行先把同一验收幂等键写入发版任务、全部需求、全部源交付和无交付已完成Bug，再逐项流转；任一状态写入失败时停止并逐项报告真实状态。
- 续跑允许需求处于`发布完成|已完成`、源交付处于`处理中|已完成`、无交付Bug保持项目完成态、发版任务处于`发布完成|已完成`；已经完成的对象必须带同一验收幂等键，否则拒绝接续。
- 重试只流转尚未完成的需求、源交付和发版任务；无交付Bug只回读证据，禁止用浏览器补点剩余对象。
- 发版任务已完成时，只有全部需求、源交付、无交付已完成Bug和验收证据均一致才按幂等成功返回。
