# 明镜止水 · 习惯（habits）

> **升档才读**：校验交棒通过、准备改代码、双轨切换、交付回执时。  
> 激活禁止默认读。

## 0. 总原则

1. **镜**：只反射交棒包；不发明产品决策  
2. **止水**：缺项 / 歧义 / 待拍板 → 先静（提问），再动  
3. **双轨**：A 可点 → 点头 → B 可跑；禁止一次偷跑两轨（除非 `B_only` 已确认）

## 1. 开干前检查清单

```text
□ 交棒包必填齐全（handoff-from-pm §1）
□ 已复述轨指令与本轮边界
□ 待拍板已处理（带病开工须本尊书面允许）
□ 工作区正确：轨 A → oneos-v2；轨 B → oneos-prod 子仓
□ 云效/push 本轮不做（除非本尊已批）
```

## 2. 轨 A · 原型（oneos-v2）

1. 读 PRD 路径文件；对照验收条拆任务  
2. 改/建 `src/prototypes/{id}/`；遵守仓内 OneOS V2 规则（DESIGN、V2Button、一原型一项等）  
   - **二次态（言出法随 §3.0.7）**：台账有查看/编辑 → 同页做满详情/编辑 UI；禁 Toast 冒充；交棒「同页二次态」节须可对账  
3. 行为/流程/门禁 **必须**可在预览点通；禁 Grep/HTTP200 假绿  
4. AutoPRD：涉及行为文案流程时同轮更新 `.spec/requirements-prd.md` + annotation（与仓规一致）  
5. OSS 口令门：若本轮要 publish 业务页 → 须有 `lingniu` 门（仓规）  
6. **通关**：交付回执 + 预览路径 + 必点清单；`A_then_B` 明确「等点头进 B」

### 2.0 跨入口跳转形态 · 默认 B1（v1.0.9 · 本尊 2026-08-15 拍板）

工作台待办 → 业务处理表单（现网常跨域名）：**默认 B1**。

| 候选 | 含义 | 侧栏 | 默认 |
|------|------|------|------|
| **B1** | 独立原型目录（工作台 + 目标业务各一项，链跳） | 两项 | **✅ 默认** |
| **B2** | 同目录 `#page=` 可分享处理页 | 仍一项 | 例外须交棒/本尊点名 |
| **B3** | 同页 `panel` 切态 | 一项 | 仅模块内二次态（A 轨），**不作**跨入口默认 |

**选型依据**：现网工作台已是链到独立业务页/域；原型应对齐「入口原型 → 目标业务原型」，**不以仓内旧同页嵌处理冒充现网**。

**硬底线**：跳转目标必须有完整表单/分区 UI；禁止 Toast「已跳转」装闭环。  
**存量**：仓内工作台/待办仍把处理页糊在同页或 Toast 的，**不参考旧实现**；交 **言出法随** 按 B1 改（独立目标原型 + 链跳）。明镜本轮只回写默认，不扫改业务原型。

**与 A 轨**：模块内 list/detail/edit 仍走言出法随 §3.0.7（同页做满）；**跨入口**走 B1，两轨不混。

### 2.1 与言出法随窄例外的冲突

若发现原型上有言出法随刚改的**行为**（非纯文案样式）与交棒不一致：

1. **以交棒包为准**停手提问  
2. 禁止静默覆盖又不报偏差  

### 2.2 壳 · 登录 · 台账视觉对表（v1.0.10）

交棒含「像素对表 / 壳 chrome / 冻结列 / 登录主题 / 顶栏」或填了**视觉锚点**时，轨 A/B 交付前勾：

```text
□ 有视觉锚点（现网 URL 或截图）；无则回执 deviationCode=visual / 待拍板
□ 顶栏：图标钮 / 通知铃 / 用户区 — 对照锚点，禁只换 Token 色装通关
□ 台账：冻结列横滚不错位；下拉/筛选不盖死表头
□ 登录：主题桥与交棒能力条一致；禁「能登」冒充能力对照（P2）
□ 配对仓规：oneos-prototype-prod-visual-parity（禁「骨架通关」）
```

纯行为门禁、无视觉范围 → 本表可跳过。

## 3. 轨 B · 真码（oneos-prod）

1. 先 Read [`repo-runtime.md`](repo-runtime.md)，再读本机 `~/oneos-prod/docs/repo-map.md` / `runtime.md`；若存在再读 `docs/v1-architecture.md`（有则读，没有不编）  
2. 默认只动核心三件套：`ln-one-os-web` / `ln-asset-management` / `ln-cloud`  
3. 非核心仓（ocr / energy-v2 / mini / xiaolingling…）→ 须交棒真仓锚点或本尊点名  
4. 分支：跟各仓默认开发分支（web=`develop`；backend 多=`dev`）；**新功能分支**须本尊确认命名/是否开支  
5. 实现须对照同一份验收；库表缺失 → 标缺口，禁止假数据装闭环（除非交棒允许演示种子）  
6. **通关**：本机可登录（见 runtime）+ 必点清单绿 + 回执；不默认 push / 提 MR  

### 3.0 真仓四闸（v1.0.3）

1. **原型 ≠ V1**：禁止用 `oneos-v2` 原型的表名/字段/接口顶现网结构。现网锚点以真仓 Controller + `@TableName` 为准。  
2. **禁默认整套 V2 仓**：V1 八仓保留、同仓演进 V2 体验。禁止为「做 V2」再 clone 一套 Git。**例外**：整域换库换服务（如 `ln-energy-v2`）须交棒点名新仓 + 新网关前缀。  
3. **定表跟前端接口**：氢/能/跨库不得预判 `ln_asset_management` vs `ln_energy_v2`。链：页面 → `ln-one-os-web/.../src/api` URL 前缀 → 网关 → 服务 → `@TableName`。交棒只写「改氢能表」而无页面/接口路径 → **停、回缺项**。表名单不进 Skill，以本机 `docs/v1-architecture.md` §8.1 为准。  
4. **禁写产线库**：只读探针 / `--no-data` 灌本机沙箱；禁止对产线执行 INSERT/UPDATE/DELETE/DDL。  

### 3.1 本地工程取舍（可自决）

下列可自决，但须写入回执「工程说明」：

- 文件拆分、命名、无明显行为差异的重构级整理  
- 本机 profile / 端口已在 runtime 钉死的服从项  

下列**不可**自决（须问本尊或回交棒）：

- 新增/删除用户可见字段与门禁  
- 改状态机、审核流、金额/权限规则  
- 引入新中间件或改 Nacos 生产向配置  
- 新建 Git 仓 / 整套 V2 仓翻倍  
- 对产线数据库写入  

### 3.2 轨 B 最低通关清单（v1.0.10 · 可勾）

进 `~/oneos-prod` 后，回执「已实现」须能对照（与 `repo-runtime` §3 / §3b 一致）：

```text
□ 网关直连可用（禁 discovery.ip=127 当万能修复）
□ /auth/login 成功（前端 RSA；禁裸 curl 当通关）
□ getInfo + getRouters 经网关绿
□ 交棒正路径可点（页面/菜单锚点）
□ 交棒逆路径或门禁可演示（至少一条）
□ 若有视觉锚点 → §2.2 勾齐或书面缺口
□ 未 push / 未合 Master（除非本尊已批）
□ 回执含 mj-receipt（passed / deviationCode）；有偏差 → twin-linkage §2c
```

缺表 / workflow DOWN / RO2013 → **标缺口**，禁止装业务正路径闭环。

## 4. 禁脑补（叠加 boot Y2b/Y2c）

| 禁止 | 正确 |
|------|------|
| 「一般系统都会…」补产品规则 | 问本尊或标待拍板 |
| 交棒没写的筛选项/按钮 | 不做；或提问是否加 |
| 空营业时间填 08:00-22:00 | 留空 |
| 验收没写的「顺手优化」大改 | 另开交棒或本尊点名 |

## 5. 云效与远程

- **默认不做**：建【开发】任务、改需求状态、push、合 Master  
- 本尊说「可以推 / 提 MR / 写云效」→ 再动；仍建议短确认目标分支  
- 与 `yunxiao-development-delivery` 重叠时：本机模拟归明镜；云效树归开发 Skill，禁止双建冲突树
