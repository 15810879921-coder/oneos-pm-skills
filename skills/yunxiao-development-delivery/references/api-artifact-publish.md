# Maven API 包受控预发布

## 目的与边界

当本次已验证的代码修改改变了 Maven 公共 API 包，而后续测试流水线会从制品仓拉取该包时，必须先发布并验证新的 **SNAPSHOT** 包，避免流水线编译到旧接口。

这只准备开发/测试依赖：不发布 release 坐标、不写生产制品仓、不修改任何流水线配置，也不等同于上线。流水线是否刷新 SNAPSHOT 仍需按本规则单独核验；单纯 `mvn deploy` 不能证明流水线一定取到了新包。

仅在 `提交代码`、`完成开发`、`完成修复bug`、`修复bug` 或批量 Bug 的统一提交阶段执行。`开始开发`、`开始修复bug`、方案模式和编码阶段不得执行 `deploy`。

## 何时需要发布

先从本次事项拥有的 Git diff 和 Maven reactor 解析模块，不能只按目录名猜测。以下全部成立才判为“需要 API 预发布”：

1. 变更位于某 Maven 模块的 `pom.xml`、`src/main/**` 或会进入主制品的资源；仅 `src/test/**`、文档、构建输出或未归属改动不触发。
2. 该模块的实际 `artifactId` 以连字符分词后包含 `api`，或该模块是只聚合这类 API 子模块的 Maven 父模块；父 POM/版本变更导致候选不唯一时停止并列出候选。
3. 当前事项的分支、改动摘要和本地提交已通过既有提交门禁；不得发布未归属或未验证的本地代码。
4. Maven 生效版本以 `-SNAPSHOT` 结束；实际 `distributionManagement.snapshotRepository` 与本机 settings 中同 ID 的凭据引用均可读取。只报告 ID/布尔结果，绝不输出 URL、用户名、密码或令牌。

不满足上述条件时写 `API包发布：不适用`，继续原提交流程。若坐标是 release、目标仓不唯一、凭据未配置、API 模块边界无法确定或前置验证失败，则 API 发布零写入并停止依赖该包的流水线动作；普通代码提交是否可继续，按原提交门禁和实际影响如实报告。

## 受控顺序

1. 先完成既有分支—事项一致性、任务归属、差异范围和开发验证门禁；保存当前仓库基线。
2. 先创建本次任务拥有的本地提交并记录 SHA，但在 API 发布回读前不得推送、合并或启动依赖该包的测试流水线。批量 Bug 按“仓库 + 目标分支”分组，每组最多一次。
3. 从 reactor 根目录使用项目已有 Maven Wrapper 或已验证 Maven，按解析出的 API 模块执行最小范围的 `-pl <模块> -am deploy`。仅在本次已完成相应验证后才允许追加项目既有的跳过测试参数；不得切换 profile、改版本、改锁定配置、清理共享本地仓库或为发布临时修改 POM。
4. 发布命令成功后，使用新的临时本地 Maven 仓库和强制 SNAPSHOT 更新重新解析每个已发布坐标；将解析到的坐标、来源提交、制品摘要和时间写入本地 receipt。解析失败、坐标不一致或无法唯一对应本次提交时，停止后续推送/MR/流水线，且不得用第二次 deploy 覆盖重试。
5. 在对应开发任务或 Bug 中追加并回读一条 `【API包发布记录】`，再继续原有推送、MR 与合并动作。

自动触发目标分支流水线时，API SNAPSHOT 必须在该目标分支合并前完成上述回读；若随后 MR 未能合并，保留“预合并 SNAPSHOT 已发布”的事实，不得用覆盖式 deploy 伪回滚。手动测试流水线则在 API 发布和合并版本均已回读后才允许启动。

## 流水线刷新门禁

在启动或附着任何依赖该 API 包的测试流水线前，读取实际流水线定义或构建脚本，证明以下任一条件：

- Maven 命令显式使用 `-U`；
- 该流水线每次使用新的 Maven 本地仓库；
- Maven 的 SNAPSHOT 更新策略已明确为 `always`。

三者都无法证明时，记录 `API包已发布，流水线刷新策略未验证`，并阻止该 Skill 启动或确认该条流水线；不得把本机 deploy 成功写成流水线已可用。修复流水线缓存策略属于独立、显式授权的流水线改造，不在本规则内执行。

## 审计记录与幂等

`【API包发布记录】` 使用一条评论承载一次源码提交的发布事实：

```text
事项：<开发任务或BUG编号>
仓库：<仓库名>
源码提交：<SHA>
API 坐标：<groupId:artifactId:version，多个用逗号分隔>
目标仓：<snapshotRepository ID>
发布结果：成功|不适用|阻塞
消费者重新解析：成功|失败；<制品摘要或失败原因>
流水线刷新门禁：已满足（-U|新本地仓库|always）|未验证
记录时间：<Asia/Shanghai 精确时间>
```

同一“仓库 + 提交 SHA + API 坐标 + snapshotRepository ID”已有成功回读记录时不得重复 deploy，只重新核验消费者解析与流水线刷新门禁。评论或远端解析不能回读时，不得声称发布成功。

发布过程不得输出或持久化密码、令牌、仓库 URL、settings 正文或业务数据；不得运行 release deploy、生产流水线、强推或覆盖式回滚。
