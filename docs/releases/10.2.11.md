# 10.2.11：Bug 修复完成与测试部署分开

用户确认先修复代码收口节点：开发验证 → 提交 → 创建或复用 MR → 合并 → 官方回读。开发验证通过、MR 实际合并且合并版本可核验后，允许 Bug 进入“已修复”。测试流水线未运行不再阻塞修复完成。

## 本次变化

- Codeup 预检保留身份、权限、分支、提交基线；不再查询或要求 Flow。
- 合并前重新核验源提交；失败分组保留 Bug 归属，防止漏掉失败仓库。重试复用已合并 MR。
- `set-status` 使用合并回执和真实开发验证清单，核验快照、用户、所有相关分组、MR、版本和报告哈希；写前再读 MR。
- 同次工作项更新写入“已修复”及描述中的受管修复记录，保留原描述、负责人、验证者，并回读。记录修复说明、验证结果、仓库、目标分支、MR、合并提交，明确“待部署、待交付测试”，`qaReady=false`。
- 重复操作幂等；重新打开后的新修复保留旧记录；不同证据不能覆盖已修复单的既有交测记录。
- 旧 Bug 自动流水线入口停用且不写 Flow，防止旧会话继续自动部署。独立“执行测试流水线”命令及范围交棒包不在本次修改范围。
- 单 Bug 与批量 Bug 命令文档统一此口径；批量适配器仍只操作当前用户快照，单 Bug 原有负责人权限边界保持。

## 保留的门禁与边界

实际合并与开发验证仍是硬条件，不能用提交、MR 已创建或部署成功替代。已修复不表示测试环境包含修复；QA 复测/关闭仍需核验真实部署版本与测试证据。10.2.10 的完成开发产品交接硬门禁保持不变。

本次只发布 Skill 和工具修复，没有更新真实 Bug 状态、执行测试流水线或修改业务代码。Codex 用户级安装需回读文件及版本；Cursor 历史包保持不变。

## 验证

新增修复完成回归测试覆盖无 Flow 收口、MR 实际合并与回读、源提交漂移、报告/版本/范围校验、写前归属复核、幂等及重新打开后的历史保留。全套生命周期测试、索引、交接约束同步、语义路由、每日更新器与 Codex 安装包一致性检查随发布运行。测试使用隔离临时文件与官方接口模拟，不冒充真实云效写入或实际测试环境验收。
