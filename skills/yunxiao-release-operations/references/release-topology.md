# 发布拓扑

发布拓扑由冻结范围的终端标签与代码资产决定，不由流水线名称猜测。仅支持以下两种正向模式：

| 模式 | 终端 | 必要资产 |
|---|---|---|
| `pc_single` | `PC` | 一个或多个实际变更组件；不得出现第二终端 |
| `shared_service_dual` | `PC` + 第二终端（默认可标为`小程序`） | 至少一个`shared_service`组件，第二终端可有自己的客户端组件 |

共同规则：

- 终端数量不决定流水线数量；只部署有代码变更的组件。
- 每个`deployRequired=true`组件都必须有已测 feature/fix 来源、`release/<迭代>`、已合并`master`的证据，以及源分支为`master`的生产流水线。
- `deployRequired=false`组件必须明确为`无需部署`，不得带生产流水线。
- 双端的共享服务只部署一次；两个终端共同使用其成功证据。PC/第二客户端是否部署，仍取决于其客户端是否有代码变更。
- 除`PC`和明确第二终端外的混合或未知终端停止，要求用户说明版本拓扑。

使用 `scripts/validate_release_topology.py` 对冻结 JSON 做无副作用校验。它只验证结构和规则，不创建分支、不读取云效、不运行流水线。
