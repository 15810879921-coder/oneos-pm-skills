# 发布运行时与写入顺序

本Skill可使用已授权的云效连接器、API或已登录浏览器会话执行真实操作。浏览器只用于读取和明确的表单操作；状态、关系、执行ID和回调必须由接口或页面回读确认，不能只凭点击成功提示。

## 固定顺序

1. 读取组织、项目、迭代、工作项、正式关系、流水线定义和当前执行。
2. 运行本Skill脚本完成范围分类或回调校验；脚本返回阻塞时零写入。
3. 展示将写对象、源状态、目标状态、幂等键和不可执行项。
4. 只执行当前口令授权的最小写入、流水线启动、冻结的生产验证计划或精确回滚。
5. 生产流水线成功时先保持发布中，执行冻结的生产验证计划；验证失败时保存问题证据并进入同一自动回滚分支，验证全部通过后才允许发布完成。
6. 重新读取工作项状态、正式关系、流水线执行ID/环境/状态、生产验证证据、问题/回滚证据区块和幂等键。
7. 等待5–30秒再读一次后继状态；异步执行、观察窗口和回滚期间每次等待不超过60秒，并持续给出简短进度。
8. 输出真实结果。部分成功必须逐项列明，不使用“整体成功”掩盖。

## 回调

回调原始Body必须原样保存用于验签，不得先重新序列化。使用：

```powershell
skill-run verify_release_callback.py `
  --body callback.json `
  --signature '<HTTP签名头>' `
  --timestamp '<HTTP时间戳头>' `
  --release-task-id TASK-900 `
  --execution-id EXEC-123 `
  --environment prod `
  --scope ONEOS-1,ONEOS-2 `
  --idempotency-key release-...
```

密钥只从`YUNXIAO_RELEASE_WEBHOOK_SECRET`或显式指定的环境变量读取。脚本不得打印密钥。验签、时间窗、执行ID、环境、范围、发版任务和幂等键任一失败时禁止状态写入。

## 不允许降级

- 不能因API不可用就用标题模糊匹配或手工猜状态。
- 不能把流水线启动成功当作执行成功。
- 不能把生产流水线成功当作业务上线成功；冻结的生产验证未完成时保持发布中。
- 不能把test执行、交接文字或聊天记录当作prod证据。
- 不能在日志无权限或回调无法验签时补写“发布完成”。
- 不能因监控不可用、证据缺失或状态未知自动回滚；只有明确失败证据或冻结计划的失败阈值才可触发。
