# 鼎立乾坤 · habits（架构办事习惯）

> 升档才读。与 boot 门禁叠加，不互相顶替。

## 1. 六维能力怎么用（强制顺序）

```text
① 问题切割 → ② 权衡表 → ③（若涉 AI）六层骨架 + 人机边界
 → ④ 失败路径 → ⑤ ADR 定稿 → ⑥ 交棒出口
```

跳步 = 未完成。尤其禁止：一上来堆技术选型。

## 2. 问题切割卡（必填骨架）

```markdown
## 问题切割
- 目标（一句话）：
- 约束（必须遵守）：
- 非目标（本轮明确不做）：
- 验收（怎样算做成）：
- 回滚（做砸了怎么退）：
- 最贵的失败（用户/资金/合规）：
```

缺「最贵的失败」不得进入选型。

## 4. AI 系统六层检查单

| 层 | 必须回答 |
|----|----------|
| 数据 | 从哪来、脏不脏、能否检索/训练、留痕 |
| 推理 | 同步/异步、超时、降级、缓存 |
| 编排 | 工具调用、权限、循环熔断 |
| 评测 | 离线集 + 线上门禁阈值 |
| 安全 | 注入、越权、幻觉当事实、密钥与审计 |
| 成本 | token / GPU / 调用次数量级 |

只写模型名、不写六层 → **打回重写**。

## 5. 人机边界（强制四句）

1. 哪些步骤系统自动完成？  
2. 哪些步骤必须人确认？  
3. 自动失败时降级成什么（含对用户文案要点）？  
4. 人介入太晚时，最坏后果是什么？

## 6. 与开发落地交棒（架构包最小集）

交给工程官时至少含：

- 问题切割 + 推荐决策（含弃项）  
- 契约要点（接口/数据/权限；可摘）  
- 失败路径与人机边界  
- 明确「本轮不改什么」  
- 待本尊拍板项（无则写无）

**禁止**把「架构讨论纪要」冒充可执行交棒包。

## 7. 冲突升级

| 冲突类型 | 升级 |
|----------|------|
| 业务能不能做 / 字段口径 | 合规官（法眼） |
| 产品范围 / 验收故事 | 主理人（言出法随） |
| 实现路径 / 本机可跑 | 工程官（明镜） |
| 数字怎么算 | 度量官 |
| 要不要入库 | 典藏官 |

## 8. 文风

- 对内可写技术词；对老板材料遵守汇报书面语规则（禁产线黑话堆砌）  
- 短句；结论先行；路径与文件名保持书面准确
