# 岗位自动介入协议

用户确认：2026-09-14。目标是需要哪个岗位，就自动引入哪个岗位，并保留结果及交接记录。无需用户逐次点名技能。

## 两层分工

先判断工作需要哪些岗位，再按 `team-task-router` 选择执行模型。岗位说明负责工作方法、责任和验收；Luna / Terra / Sol 负责执行能力与成本。模型派工成功不能替代岗位介入证据。

| 工作意图或当前阶段 | 必须介入的岗位 | 默认技能 |
| --- | --- | --- |
| 页面设计、原型视觉、布局、组件、交互、界面改动、体验评审 | 体验规范 `ux` | `oneos-ux-guide` |
| 需求分析、需求整理、功能范围、用户流程、验收条件、PRD、产品方案 | 产品交付 `product` | `oneos-pm-product` |
| 修改或审查代码、修复缺陷、调试本机服务、启动或排查开发环境、构建和依赖问题 | 开发落地 `development` | `oneos-dev-delivery` |
| 写或执行测试、回归、复测、验收验证、缺陷验证、测试报告 | 测试验收 `qa` | `oneos-qa-verify` |

### 混合任务

- “梳理需求并改页面”：先产品交付确认需求，再由体验规范给页面方案；写代码阶段引入开发落地，验证阶段引入测试验收。
- “按钮颜色改一下”：体验规范介入；涉及源码修改时开发落地介入；验证只覆盖这次变化，不扩成全量业务测试。
- “本机服务启动失败”：开发落地先定位；执行验证时测试验收介入。不能因为是只读排查就跳过开发岗位。
- “只分析需求，先别改”：产品交付介入，停在分析授权范围；不得根据提到“改”或“测试”就擅自执行后续阶段。
- 普通翻译、读文档、整理表格、时间查询不因使用命令工具就自动算作开发工作。工具是手段，用户任务与当前阶段决定岗位。

## 作用域与授权

项目已有同类岗位技能时优先使用，例如玉衢项目对应 `yuzar-pm-product` / `yuzar-dev-delivery` / `yuzar-qa-verify`。项目的业务规则、资料来源、权限及验收要求继续有效。

当前工作目录只用于推荐项目技能，不能证明实际任务归属。操作全局配置、跨项目文件，或实际目标与当前目录不同，主助手必须按目标主动填写 `job_role_skills`；通用工作选择默认岗位技能并限用通用方法。这个判断由助手自动完成，不要求用户逐次点名岗位或填写参数。

没有项目专用技能的通用工作，可使用默认技能的岗位方法；只消费需求完整性、体验原则、开发理解和验证方法等通用部分，不把 OneOS 的业务口径、真仓路径、数据权限或发布动作引入别的项目。项目专用技能所需的账号资料缺失时如实标明，不编造安装包或业务依据。

用户已确认的局部变更直接执行。岗位介入不新增重复确认，也不扩大功能、文件、环境、外部写入或发布授权。

## 什么算已经介入

1. 任务或阶段记录所需岗位及各自责任。
2. 承担岗位的主助手或子代理完整读取对应技能入口正文。优先使用 `role-read` 或 `cat`，为输出保留足够容量；不能用固定行数的 `head` / `sed` 截断长技能后就标为读取完成。仅出现在技能目录、用户消息、引用材料、工具输出或口头宣称中，不算读取证据。
3. 承担者按该岗位方法完成本阶段工作，并给出具体结果、产物或验证证据。
4. 有后续岗位时交接目标、已确认边界、当前产物、未决问题和验收点；没有后续阶段则写明本阶段已收口。

记录应分别表达：要求介入、技能已读、结果已记录、已交接。缺失时保留缺口，不能把“已分配”写成“已完成”。同一任务中已经成功读取且仍有效的技能可以复用，无需反复读取。

## 主助手与子代理

岗位可由主助手承担，也可由按模型路由选出的子代理承担。不为凑岗位名单创建多余代理；宿主的独立子任务和父任务独立工作限制继续有效。

子代理收到任务后，按本子任务范围确定岗位并实际读取对应技能；未收到岗位说明时也不能省略。子代理不重走主任务模型路由、不递归派工。交付中写清承担岗位、结果及证据，再回主任务验收。

## 原生机制的边界

全局 `AGENTS.md` 和角色配置提供常驻指令；根任务的 `UserPromptSubmit` 提供本轮岗位提示，受覆盖的 `PreToolUse` 检查派工和岗位读取证据，`PostToolUse` 接收派工回执，`Stop` 保存审计结果，不自动制造额外收费轮次。

子代理不走根任务模型评估；当前原生子代理分支只阻止递归派工。子代理的岗位介入由常驻岗位指令驱动，父任务须核对子代理真实读取、产物及交接，必要时登记结果。不能把这描述成对子代理每一步也有完整的原生岗位强制检查。

只有完成原生信任并拿到真实事件及交付回执，才能称为原生自动检查已生效。命令行检查、单元测试和手动构造的事件仅证明各自检查结果，不冒充原生触发。未覆盖的工具路径及识别不确定性必须保留说明。
